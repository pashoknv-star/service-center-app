## 2. Модель данных (schema v15, SQLite)

sql

```sql
-- Справочник ТС. Водитель по умолчанию = employees.id (группа «Транспорт»).
CREATE TABLE vehicles (
    id                TEXT PRIMARY KEY,
    model             TEXT NOT NULL,          -- название/модель
    plate             TEXT NOT NULL,          -- госномер
    location          TEXT,                   -- населённый пункт нахождения
    in_service        INTEGER NOT NULL DEFAULT 1,  -- 1 «в строю» / 0 «ремонт»
    default_driver_id TEXT,                   -- водитель по умолчанию (подставляется, можно заменить)
    sort_order        INTEGER,
    created_at TEXT, updated_at TEXT
);

-- Заявка абонента (ручное создание в 1-м релизе; n8n — только заготовка, см. п. 8).
CREATE TABLE subscriber_requests (
    id          TEXT PRIMARY KEY,
    title       TEXT NOT NULL,              -- краткое название/суть
    client_note TEXT,
    zone_id     TEXT,                       -- зона, определяется вручную при распределении
    status      TEXT NOT NULL DEFAULT 'new'
                CHECK (status IN ('new','assigned','in_progress','done','cancelled')),
    version     INTEGER NOT NULL DEFAULT 1, -- optimistic concurrency
    created_by  TEXT,
    created_at  TEXT, updated_at TEXT, done_at TEXT
);

-- Назначение: заявка → ТС + водитель + бригада + время. Одна заявка → много назначений.
CREATE TABLE request_assignments (
    id           TEXT PRIMARY KEY,
    request_id   TEXT NOT NULL REFERENCES subscriber_requests(id) ON DELETE CASCADE,
    vehicle_id   TEXT NOT NULL REFERENCES vehicles(id),
    driver_id    TEXT NOT NULL,             -- employees.id (любой, не только «Транспорт»)
    work_date    TEXT NOT NULL,             -- 'YYYY-MM-DD', локальное +05
    start_time   TEXT NOT NULL,             -- 'HH:MM', шаг 30 мин
    duration_min INTEGER NOT NULL CHECK (duration_min % 30 = 0 AND duration_min > 0),
    version      INTEGER NOT NULL DEFAULT 1,
    created_by   TEXT,
    created_at   TEXT, updated_at TEXT
);
CREATE INDEX idx_ra_vehicle_date ON request_assignments (vehicle_id, work_date);
CREATE INDEX idx_ra_driver_date  ON request_assignments (driver_id, work_date);

-- Бригада: просто список employee_id (без имени бригады; можно из любых зон, кроме — по вашему п. 5 — Транспорта).
CREATE TABLE assignment_crew (
    assignment_id TEXT NOT NULL REFERENCES request_assignments(id) ON DELETE CASCADE,
    employee_id   TEXT NOT NULL,
    PRIMARY KEY (assignment_id, employee_id)
);

-- Маршрут: обязательны только выезд и приезд; промежуточные — опционально.
CREATE TABLE assignment_waypoints (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    assignment_id TEXT NOT NULL REFERENCES request_assignments(id) ON DELETE CASCADE,
    ord          INTEGER NOT NULL,          -- 0 = выезд, N = приезд (последняя)
    kind         TEXT NOT NULL CHECK (kind IN ('departure','intermediate','arrival')),
    address      TEXT NOT NULL,
    planned_duration_min INTEGER,           -- только для intermediate; шаг 30
    travel_from_prev_min INTEGER            -- время от предыдущей точки, шаг 30
);
```

Аудит — существующий `audit_log` (`action`: `request.create/update/status`, `assignment.create/update/delete`, детали — JSON с `warnings_confirmed`).

## 4. Проверки и предупреждения (warn + confirm + audit, ничего не блокирует)

1. **Пересечение по времени** того же ТС или водителя в этот день.
    
2. **Сумма маршрута**: `Σ travel_from_prev + Σ planned_duration` (промежуточные) vs `duration_min` — расхождение → предупреждение.
    
3. **Отпуск/командировка**: водитель или член бригады имеет запись в `schedule_entries` на эту дату или участвует в `trips` на этот период.
    

Схема: `POST` возвращает `409-style` не ошибку, а `{"warnings": [...]}` с `draft_id`; клиент показывает диалог «Всё равно назначить» → повторный `POST` с `confirm: true` → в аудит пишется факт подтверждения.
