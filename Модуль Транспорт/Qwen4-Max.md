## 4. Жизненный цикл и права

`новая → распределена → в работе → выполнена`, `отменена` — из любого нетерминального статуса.

- **распределена** — автоматически при первом назначении; удаление последнего назначения возвращает в **новая**.
- **в работе** — admin или супервизор зоны заявки.
- **выполнена / отменена** — **только создатель заявки (`created_by`) и admin** (ваш п.8). Терминальные статусы — read-only, переоткрытие — в бэклог.

|Действие|admin|supervisor своей зоны|supervisor чужой зоны|viewer|
|---|---|---|---|---|
|Просмотр доски/реестра/ТС/водителей|всё|заявки своей зоны; ТС и водители — все|заявки своей зоны|всё, read-only|
|Справочник ТС (создать/править/ремонт/удалить)|✅|—|—|—|
|Создать/править заявку|любая зона|своя зона|—|—|
|Назначение (ТС+водитель+бригада+маршрут+время)|✅|своя зона; бригада — сотрудники своей зоны; водитель — любой из g6; ТС — любое|—|—|
|«В работу»|✅|✅|—|—|
|«Выполнена»/«Отменена»|✅|только свои созданные|—|—|

RBAC — на существующем `can_edit_group()` / `scope_group_id` из `api/auth.php`, новые роли не заводим. Все проверки — на сервере, скрытие кнопок — дополнительно на клиенте.

## 5. API — `api/transport.php` (стиль `tasks.php`: resource + action, JSON, version/409)

|Запрос|Назначение|
|---|---|
|`GET ?resource=board&from=YYYY-MM-DD`|неделя: vehicles + requests + assignments (crew, stops одним пакетом), RBAC-фильтр по зоне|
|`GET ?resource=requests&status=new`|очередь «Нераспределённые»|
|`POST/PUT ?resource=requests` · `PUT …&action=status`|CRUD заявки (аудит), смена статуса с проверкой «создатель/admin»|
|`GET/POST/PUT/DELETE ?resource=vehicles`|справочник (запись — admin; DELETE с назначениями → 409 `vehicle_has_assignments`)|
|`POST/PUT/DELETE ?resource=assignments`|назначение; `dry_run=1` → список предупреждений без записи; `force=1` → запись + аудит|
|Ошибки|401/403, 400 `invalid_*`, 409 `VERSION_CONFLICT` (оптимистичная конкуренция, паттерн tasks)|

## 6. Предупреждения (не блокируют) + аудит

1. **Пересечения** окна `[start, start+duration)` по **ТС**, **водителю** и **каждому члену бригады** с назначениями заявок в статусах `assigned/in_progress` (выполненные/отменённые не считаются). Несколько заявок на одно ТС подряд без наложения — без предупреждений.
2. **Доступность** водителя и бригады: `schedule_entries` со статусами отсутствия на даты назначения + пересечение с `trip_participants`/`trips` (подтверждённая командировка — предупреждение, прогнозная — пометка). Точные коды статусов отсутствия беру из исходников при реализации, не из индекса.
3. **Сумма отрезков маршрута ≠ прогнозу** — предупреждение в форме, сохранение не блокирует и подтверждения не требует.

Механика: `dry_run` → UI показывает жёлтые плашки с чекбоксами «Подтверждаю…» → повторный POST `force=1` → событие `transport.assignment.override` в `audit_log` (кто, что, какие пересечения). Остальные события: `transport.request.create/update/status`, `transport.vehicle.*`, `transport.assignment.create/update/delete`. Учтите: `audit_log` чистится через 7 дней (существующая политика E5-4) — более长ее хранение журнала решений — в бэклог.

## 7. UI

- Новая вкладка **«Транспорт»** в `index.html` + модуль `js/transport.js` (паттерн `js/tasks.js`), гейтинг через `applyRoleGating` / `public_user`.
- **Неделя**: строки — ТС (модель, госномер, населённый пункт, «в строю»/«ремонт», водитель по умолчанию); колонки — 7 дней × 48 получасовых ячеек 00:00–23:59; горизонтальный скролл + липкая левая колонка (паттерн матрицы отпусков); «Сегодня» считается по **+05**, не по браузеру; строка «ремонт» — серая штриховка. Клик по блоку → карточка (макет 2), клик по пустой ячейке / заявке из очереди → форма распределения (макет 4). Выполненные/отменённые на доске скрыты, видны в Реестре.
- **Форма**: ТС (только «в строю») → водитель подставляется из ТС, заменяем → бригада-чипы из сотрудников зоны заявки → начало + длительность степпером 30 мин → редактор маршрута (выезд/приезд обязательны, «+ промежуточная точка», минуты между точками, live-сумма против прогноза).
- Карточка заявки: «+ назначить ТС» (второе назначение), «В работу», «Выполнена», «Отменена» — по роли; у заявки с 2 ТС в Реестре строки связаны значком (макет 3).
- Обновление: polling 30 с + кнопка; конфликт версий → тост и перезагрузка доски. Мобильные 375px: режим «День», скролл только внутри контейнера доски.
