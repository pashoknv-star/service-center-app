# V10-T4 — SPIKE_MAP: карта для модуля «Транспорт» (Leaflet + OpenStreetMap, геокодер, маршрут)

**ВЕРДИКТ (проверено 2026-11-21, коммит основания `30af063`).** Реализуемо без ключей и без платных сервисов: **Leaflet 1.9.4 локально (`js/vendor/leaflet/`) + тайлы `tile.openstreetmap.org` напрямую из браузера + Nominatim (поиск/обратный геокод, только через прокси) + OSRM `routing.openstreetmap.de` (маршрут, только через прокси)**. Прокси `api/transport_geo.php` — единственная точка исходящих запросов; наружу уходят только название населённого пункта и координаты (3 знака, ≈100 м).
**Запасной вариант:** маршрут — OpenRouteService (бесплатный ключ Standard: 2000 расчётов/сутки; коммерческое использование разрешено ответом HeiGIT) → затем Valhalla FOSSGIS; геокодер — Photon (komoot); тайлы — другой поставщик из списка OSM. Адреса поставщиков — в конфиге, не в коде (требование OSMF).
**Главные риски:** (1) все сервисы — публичные «добровольческие» без SLA, блокировка возможна без уведомления → форма обязана работать вручную (деградация описана, прототип проверен); (2) исходящий HTTP хостинга Hostland **не проверен** (только документ: расширение `curl` есть) — владельцу дана команда, §7; (3) OSM-данные не знают сезонности: пара Междуреченский — Кондинское считается «дорогой» (85 км без названий, 46 км/ч), а по справочникам это зимник → оценка карты — подсказка, не истина; (4) условия: у OSRM-демо в вики «non-commercial», у FOSSGIS — «коммерческое допустимо, если сервис не существенная часть предложения»; нужно согласие владельца (§8); (5) нужен контактный e-mail проекта для User-Agent/подвала (требование OSMF и FOSSGIS).
**Округление:** секунды → `ceil(сек/900)·15`, 0 → 0, любой положительный перегон ≥ 15 мин; на реальных парах OSRM: 110,3 → 120, 164,6 → 165, 368,2 → 375 мин (§5). Точность OSRM по расстоянию на 3 парах со справочными данными — 0,2…1,1 %; Valhalla на паре Урай — Советский уходит на +21,6 % (231 км против 190).
**Нужно от владельца:** согласие с условиями 3 сервисов, e-mail, запуск проверки хостинга, выбор «OSRM-демо или сразу ключ ORS» (§8). Код приложения не менялся; публичных запросов за исследование — 44 из ~50 (журнал `T4_evidence/request_log.tsv`).

### 1.2 Тайлы OSM — политика `tile.openstreetmap.org`

Источник: <https://operations.osmfoundation.org/policies/tiles/> (прочитано 2026-11-21).

| Требование | Что это значит для нас |
|---|---|
| URL строго `https://tile.openstreetmap.org/{z}/{x}/{y}.png` (HTTP-вариант запрещён) | зашить в конфиг (переключаемо), формат `https` |
| Видимая атрибуция «© OpenStreetMap contributors» со ссылкой на `openstreetmap.org/copyright` | текст по политике — английский; в макете 7 написано «© участники OpenStreetMap» — оставить стандартную форму как в требовании владельца; не прятать под кнопки |
| Валидный `User-Agent` (браузер подходит) и **`Referer`** от веб-страницы; **нельзя** ставить Referrer-Policy, запрещающую Referer | в `index.html` и `api/*` ограничений нет (поиск `referrer|referer` по `index.html`, `.htaccess`, `api/*.php`, `router.php` — пусто); перед выкладкой проверить, что nginx хостинга не добавляет `Referrer-Policy: no-referrer`; в окне не ставить `referrerPolicy: 'no-referrer'` |
| Кэш по `Cache-Control` (≥ 7 суток, если не умеем читать заголовки) | браузер делает сам; фактический ответ: `cache-control: max-age=91490, stale-while-revalidate=604800` (≈25 ч) — `T4_evidence/tile_osm_urai_z9.png.headers` (тело тайла не хранится) |
| Нельзя: массовая выгрузка, «предзагрузка», офлайн-режим, no-cache заголовки | окно показывает только то, что смотрит пользователь; никаких prefetch |
| Допустимая нагрузка | числом не задана: «heavy use» запрещён, «умеренное число пользователей» допустимо. Оценка (моя): 5–20 диспетчеров × до 30 открытий окна × 20–40 тайлов ≈ до 10–20 тыс. тайлов/сутки пиково, реально ниже за счёт кэша браузера (25 ч) — это уровень обычного просмотра, а не нагрузки сервиса |
| Прокси-кэш тайлов | OSMF «не рекомендует»; если делать — обязан идентифицироваться своим User-Agent, не срезать Referer, держать кэш ≥ 7 суток |
| SLA | нет («best-effort»); доступ может быть закрыт без уведомления |
| Приватность | политика просит не передавать персональные данные сервису; публикуются агрегированные логи тайлов |

**Решение.** Тайлы грузит **браузер напрямую** (проксировать не нужно: на shared-хостинге на PHP это лишняя нагрузка и нарушение рекомендации OSMF). Цена: OSM видит IP сотрудников и номера тайлов (= просматриваемая область, без каких-либо данных заявок) — это нужно явно принять владельцу (§8). Если владелец не согласен — единственная альтернатива без раскрытия IP: свой тайл-прокси с отдельным User-Agent (PHP на Hostland; не проверялось, не рекомендуется OSMF).

**Если тайлы недоступны.** Leaflet шлёт событие `tileerror`; после N ошибок подряд окно показывает серую подложку и подпись «Подложка карты недоступна»; пины, поиск, расчёт маршрута и «Подставить в маршрут» продолжают работать (они не зависят от тайлов). Если Leaflet не загрузился совсем — кнопка «На карте» скрывается/неактивна, форма работает вручную (как в макете 7, блок «Нет связи с картой → закройте окно и введите значения вручную»).

## 3. Расчёт маршрута — как выбирали

Сравнивались OSRM (FOSSGIS), Valhalla (FOSSGIS), OpenRouteService (HeiGIT), GraphHopper. Профиль «автомобиль»: OSRM `driving` (на FOSSGIS — `routed-car`), Valhalla `costing: auto`, ORS `driving-car`.

| | OSRM (routing.openstreetmap.de) | Valhalla (valhalla1.openstreetmap.de) | OpenRouteService (api.openrouteservice.org) | GraphHopper Directions |
|---|---|---|---|---|
| Условия | FOSSGIS: <https://fossgis.de/arbeitsgruppen/osm-server/nutzungsbedingungen/>; вики OSRM: «разумное **некоммерческое** использование, ≤ 1 запрос/с, без гарантий» (<https://github.com/Project-OSRM/osrm-backend/wiki/Demo-server>); `about.html`: валидный UA, Referer при необходимости, attribution + ссылка «fix the map», ≤ 1 запрос/с | те же условия FOSSGIS; для приложений для конечных пользователей просят сообщить в GitHub Discussions и слать `X-Client-Id` (<https://valhalla.github.io/valhalla/start/introduction/>) | `account.heigit.org/info/tos`: **запрещено передавать персональные данные**; результаты под CC-BY-SA 4.0, атрибуция «© openrouteservice by HeiGIT \| Data from OpenStreetMap»; коммерческое использование на Standard разрешено (ответ сотрудника HeiGIT на форуме, 2026-10-12) | Free — **только некоммерческое**; платные от 69 €/мес (<https://www.graphhopper.com/pricing/>) |
| Лимиты | 1 запрос/с, ≤ 2 соединений (скрипты — 1) | 1 запрос/с; `/route` до 20 точек | Standard: Directions **2000/сутки, 40/мин**; Geocoding 3000/100 (<https://openrouteservice.org/plans/>); макс. расстояние 6000 км | Free: 500 кредитов/сутки, ≤ 5 точек, ограниченные профили |
| Ключ | нет | нет | **да** (бесплатная регистрация, e-mail организации) | да |
| Проверено с этого хоста | 200, 0,28–0,60 с (12 запросов: 7 FOSSGIS + 5 демо-хост) | 200, 0,50–0,73 с (6 запросов) | без ключа 401 `Authorization field missing` (`ors_directions_nokey.json`); **с ключом не проверялось** — скрипт `v10_t4_ors_compare.sh` готов | не проверялось |
| Self-host | возможно (C++), нужен граф региона и процесс-демон | возможно | возможно (Docker/Java) | возможно (Java) |

**Hostland — self-host невозможен:** shared-хостинг, `sudo` нет (`DEPLOY_HOSTLAND.md:16`), демоны запускать нельзя, из планировщика доступен только cron панели (`DEPLOY_HOSTLAND.md:208`), CLI PHP 5.3 (`:12`). Любой из движков требует постоянного процесса и графа дорог (порядка гигабайта для региона) — не размещается. Вариант на будущее: отдельный VPS (в проекте уже упоминается «российский VPS» под n8n — `api/tasks_rules.php:574`; его параметры мне неизвестны, решение владельца).

## 4. Прочие замеры и ограничения

### 4.1 Отказоустойчивость
Публичные сервисы без SLA (Nominatim, OSRM, Valhalla — «один сервер»; OSM tiles — «best effort»). В замерах — 41 из 44 запросов вернули 200 за 0,13–0,73 с; сбоев в ходе исследования, кроме Overpass (таймаут ×2), не было. Меры: кэш (§6.3), цепочка провайдеров OSRM → ORS → Valhalla, `degraded` без ошибки для пользователя, circuit-breaker (3 сбоя за минуту → 60 с без обращения наружу).

### 4.2 CORS
OSRM/Valhalla отвечают `access-control-allow-origin: *` — технически браузер мог бы звать их напрямую, **не делаем**: теряем белый список, кэш, лимит 1 запрос/с на приложение, управляемый User-Agent и ключ.

### 4.3 Нагрузка (оценка, моя)
Поиск/обратный/маршрут — до нескольких десятков вызовов в сутки, каждый кэшируется на 30–90 суток по ключу (повторные пары «база — пункт» не идут наружу). Лимит 1 запрос/с и дневные лимиты ORS (2000) недостижимы.

### 4.4 Стоимость
Основной набор — **0 ₽** (все сервисы бесплатные, ключи не нужны). Запас: ORS Standard — 0 €, ключ; платный GraphHopper — от 69 €/мес (не рекомендуется). Своя инфраструктура (VPS под OSRM+Nominatim) — отдельное решение владельца, не оценивалась.

### 4.5 Не получилось
- Overpass (`overpass-api.de`) с этого хоста: 2 запроса по 25 с, 0 байт, код 000 — не используем.
- ORS с ключом, GraphHopper, Valhalla «зимние» опции, эталонные расстояния по независимому сервису **с API** — не проверялись (нужны ключи/регистрация); вместо этого — 6 справочных значений с 5 сайтов (§3.2) и сравнение двух независимых движков (OSRM и Valhalla).
- Эффект Referer на тайлах с боевого домена — не проверялся (нет прод-доступа).

## 5. Округление и подстановка

**Формула** (`v10_t4_rounding.js`/`.php`, обе версии дают одинаковые результаты): вход — секунды сервиса `sec` (число, может быть дробным).
```
sec ← round(sec)                    // до целых секунд
если sec = 0         → 0            // точки совпадают
иначе                → ceil(sec / 900) × 15   // минуты, кратные 15; любое положительное → не меньше 15
sec не число / < 0 / нет маршрута → нет оценки (null)
```
Целочисленная арифметика исключает ошибки плавающей точки на границах. Считает **сервер** (прокси возвращает `{km, sec, min_map}`), клиент только показывает; `min_map` пишется в `assignment_stops.leg_min_map`, принятое пользователем — в `leg_min` (`PLAN.md:44`).

**Нулевой и очень короткий перегон.** `sec = 0` (точки совпадают или привязались к одному отрезку дороги) → результат 0, кнопка «Подставить» заменяется текстом «точки совпадают». Любое положительное время даёт **не менее 15 мин** (шаг владельца, п. 5 `00_COMMON.md`) — подсказка «меньше шага: принято 15 мин». Это правило **нужно подтвердить владельцем** (§8): альтернатива — 0 для перегонов внутри одного населённого пункта.

**Как показывать рядом с ручным значением** (по макету 7: блок «Расчёт по карте: ① → ②: 38 км · 42 мин … Округление вверх до 15 мин: 45 мин и 1 ч [Подставить в маршрут]»):
1. В окне «На карте» — для каждого перегона строка «км · мин (по карте)» и «→ 45 мин»; кнопка «Подставить в маршрут» пишет **все** перегоны разом, рядом у каждого — «подставить только этот».
2. В строке маршрута формы — принятое значение (`leg_min`) и серая метка «карта: 45», если оценка есть; если ручное ≠ карта — «карта: 45 · вручную: 60» без предупреждения-ошибки.
3. **Ничего не подставляется автоматически**: ни `leg_min`, ни тем более `duration_min` (прогноз длительности остаётся ручным — решение владельца 7). Сумма маршрута против прогноза — только мягкое предупреждение `route_sum_mismatch` (`CONTRACT.md:66`).
4. Нет оценки (`degraded`, нет маршрута, пин без второй точки) — кнопка скрыта, блок «Нет связи с картой → введите значения вручную».
5. Показывать также «по прямой ≈ N км» (считается на клиенте/сервере по координатам без внешних вызовов) — как ориентир, если сервис недоступен; в поле не подставляется.

### 6.2 Белый список входа (до любого исходящего запроса)

- **Название** (`q`): `^\p{L}[\p{L} .'’-]*$`, 2–60 знаков, ≤ 3 слов, **без цифр и запятых**, без «адресных» слов (`ул, улица, пр-кт, проспект, пер, проезд, ш, шоссе, б-р, наб, д, дом, корп, стр, кв, оф…`), без формы «Ф И О на -вич/-вна/-ична». Иначе — `error: bad_place_name`, наружу не уходит (тест: 17 «плохих» вводов — адреса, ФИО, цифры, `&format=xml`, перевод строки, `+7…` — все отклонены, ни один не создал исходящего запроса; 8 настоящих названий — «Урай», «Междуреченский», «Ханты-Мансийск», «Нижние Нарыкары», «Усть-Аха», «Старый Катыш», «Кондинское», «Советский» — проходят).
- **Координаты**: число (или числовая строка) в диапазоне, → округление до 3 знаков; иначе `bad_coords` (тест: `abc`, `91`, `181`, `60.1;x`, массив, `NaN`, отсутствие).
- **Остаточный риск (честно):** никакая проверка не отличит название посёлка от «выдуманного» слова. Адрес из одного слова без цифр и «ул.» (например, имя собственное) пройдёт. Закрывается подписью поля «Населённый пункт — без улицы и дома», отказом на цифры/адресные слова и тем, что **свободный поиск доступен только ролям с правом править заявки** (`require_edit()`, `api/auth.php:133`); при желании владельца — выбор только из справочника известных пунктов (`geo_cache` + базы).
- Лишние поля входа (`subscriber`, `address`, `title`, `phone`, любые) **игнорируются** и наружу не копируются (тест с «канарейками»).

### 6.3 Белый список выхода, кэш `geo_cache`

- **Клиенту** возвращается только: поиск — `name, lat, lon, kind, county, state` (lat/lon — 5 знаков); обратный — `name, level, county, state`; маршрут — `{km (0,1), sec, min_map}`. Улицы, номера домов, индексы, `osm_id`, `display_name`, `hint`, `waypoints[].name` — отбрасываются (тест: ни одна из таких строк не дошла до ответа клиенту).
- **Кэш** — таблица из схемы v15 `geo_cache(key, kind, payload_json, fetched_at)` (`PLAN.md:45`), хранит **уже отфильтрованный** ответ (в кэш улицы не попадают). Ключи: `search:sha1(lowercase(название))`, `reverse:<lat,lon 3 знака>`, `route:<lon,lat;lon,lat 3 знака>`. TTL: поиск/обратный — 90 суток (Nominatim требует кэшировать), маршрут — 30 суток. Сбои (`degraded`) в кэш не пишутся; «не найдено» — 1 час. Запись — короткой транзакцией, **вне** SQLite-транзакции не держать сетевой вызов.
- Служебная строка лимита хранится в той же таблице (`kind='rl'`, ключ `rl:<сервис>`), чтобы не добавлять таблиц.

### 6.4 Таймауты, лимиты, деградация

| Параметр | Значение |
|---|---|
| Таймаут соединения / общий | 2 с / 4 с (поиск, обратный), 6 с (маршрут); `CURLOPT_NOSIGNAL`; редиректы выключены; только http/https; размер ответа ≤ 256 КБ (`CURLOPT_MAXFILESIZE`) |
| Частота наружу | глобально ≥ 1,1 с между запросами к одному сервису (строка `rl:<сервис>` под `BEGIN IMMEDIATE`; тест: второй сразу после первого → `rate_limited`, наружу не ушёл) |
| Частота от пользователя | например, 30 запросов/мин на пользователя (счётчик в той же таблице); превышение → `rate_limited` |
| Сессия | вызвать `session_write_close()` до исходящего вызова (сессия — файловая: `api/auth.php:27-38`; прецедент `api/task_files.php:94`), иначе параллельные запросы того же пользователя встанут в очередь |
| Доступ | `require_edit()` (admin/supervisor; viewer — 403, как в `CONTRACT.md`); метод POST с JSON, cookie `SameSite=Lax` (`api/auth.php:33`) |
| Деградация | любой отказ (таймаут, 4xx/5xx, не-JSON, `connect_error`, `rate_limited`, circuit-breaker) → HTTP **200** `{success:true, degraded:true, reason:…}`; клиент скрывает «Подставить», показывает «Нет связи с картой — введите значения вручную»; форма и сохранение не блокируются; `leg_min_map = NULL` |
| Circuit-breaker | 3 сбоя за 60 с → 60 с ответы `degraded` без обращения наружу (чтобы не копить таймауты и не злить сервис) |
| Журнал | как у n8n: одна строка `error_log` на аномалию, без параметров и без ключей (`api/tasks_rules.php:616-631`) |
| Цепочка провайдеров | маршрут: OSRM → (ключ есть) ORS → Valhalla; геокод: Nominatim → Photon; переключение — конфигом, не обновлением ПО (требование Nominatim) |

### 6.5 Как проверить, что наружу уходит только разрешённое (тест с поддельным внешним сервисом)

Реализовано и прогнано в прототипе — **`php scripts/spike/v10_t4_geo_proto_test.php` → `RESULT: 80 passed, 0 failed`** (`T4_evidence/geo_proto_test_output.txt`):
1. Поднимается `php -S 127.0.0.1:<порт> v10_t4_fake_upstream.php` — «Nominatim+OSRM», который пишет **каждый** входящий запрос целиком (метод, путь, query, все заголовки, тело) в журнал и отвечает «грязно»: с улицами, номером дома, `hint`, `osm_id`.
2. На вход прокси подаются «канарейки» (`subscriber`, `address`, `title`, `phone` и адрес в `q`).
3. Проверяется журнал фейка: **ключи query строго из белого списка**; значения только из валидаторов; нет канареек (ни одного вхождения «Ленина», «Заявка», «ул.», «subscriber», номера); метод GET и пустое тело; `User-Agent` проекта; **нет** `Cookie/Referer/Authorization/X-Forwarded-For/X-Real-IP/Origin`; отказанные вводы не создали **ни одного** запроса.
4. Проверяется ответ клиенту: нет улиц/`hint`/`osm_id`; формы ответа фиксированы.
5. Кэш (повтор не идёт наружу), деградация (таймаут при `timeout_ms=500` → `degraded/timeout` быстрее 1,5 с; HTTP 500; не-JSON; недоступный порт; сбои не кэшируются), лимит частоты.
6. Статическая проверка «единственной точки»: в `api/*.php` (кроме `*_test.php`) исходящий HTTP сейчас только в `tasks_rules.php` (n8n) — в тесте T7 допустимый список = `tasks_rules.php` + `transport_geo.php`; любой другой файл → FAIL.
7. **Негативный контроль** (тест реально ловит утечку): в копии прокси добавлен параметр `comment=<адрес и номер заявки>` → тест падает на 4 проверках (`T4_evidence/geo_proto_negative_control.txt`).

Для T7: то же против реального `transport_geo.php` (БД-копия, вход под ролями admin/supervisor/viewer: 401/403/200), базовые URL провайдеров — из конфига/переменных окружения (в тесте — адрес фейка).

### 6.6 Где хранятся ключи
В git — никаких ключей. Основной набор (OSRM + Nominatim + Photon + OSM-тайлы) **ключей не требует**. Для ORS: PHP-файл вне репозитория `data/transport_geo.config.php` (возвращает массив: `ors_key`, базовые URL, e-mail проекта); каталог закрыт от веба `data/.htaccess:3` (`Require all denied`), как `app.db`; **в `.gitignore` строки для него нет — добавить в T7** (сейчас там только `data/*.db-*` и `data/task_files/`). Для разработки/тестов допустим `getenv()` по образцу `api/tasks_rules.php:597-607` (на проде переменные окружения не задаются — `DEPLOY_HOSTLAND.md:336-338` про n8n). Ключ в ответах клиенту и в логах не показывается.

## 7. Хостинг-кандидат (Hostland): исходящий HTTP

**Статус: не проверено.** Что известно из документов (`DEPLOY_HOSTLAND.md:11-13`): web-PHP 8.1.34 (Apache за nginx), расширения включают `curl`, `json`, `session`, `pdo_sqlite`; CLI PHP 5.3 отличается от web. Что неизвестно: разрешён ли PHP исходящий 443 (на shared-хостингах бывает закрыт), значение `allow_url_fopen`/`disable_functions` именно для web-PHP, не блокирует ли хостинг конкретные адреса. Прод-доступа у меня нет и обращаться на прод запрещено правилами задачи, поэтому — команда владельцу:

1. (быстро, из SSH `host1882970@serv18.hostland.ru:1024`): `curl -sS -m 10 -o /dev/null -w '%{http_code}\n' -A 'ServiceCenterApp-egress-check/0.1' https://nominatim.openstreetmap.org/status` — ожидается `200` (проверяет сеть аккаунта, но не web-PHP).
2. (точно, веб-PHP 8.1): положить `scripts/spike/v10_t4_egress_check.php` как `htdocs/www/_egress_check.php`, подставить в `const TOKEN` случайную строку, открыть `http://host1882970.hostland.pro/_egress_check.php?k=<строка>`, сохранить вывод, **файл удалить**. Скрипт печатает версию PHP, `curl`/`openssl`, `allow_url_fopen`, `disable_functions`, DNS и результат 2 публичных запросов (curl и fopen) с паузой 1,2 с. Локальный прогон (для образца вывода): `T4_evidence/egress_check_local_run.txt` (PHP 8.3.6, оба запроса `HTTP 200`).
3. Если исходящий закрыт — вся карта сводится к «ручной режим» (деградация), решение: попросить поддержку Hostland открыть 443 либо вынести прокси на VPS владельца (n8n) и звать его по HTTPS.

## 9. Риски и открытые вопросы

| # | Риск | Мера |
|---|---|---|
| R1 | Публичные сервисы без SLA, могут заблокировать без уведомления | кэш, `degraded`, circuit-breaker, переключаемые URL, ORS-ключ как запас; ручной ввод всегда работает |
| R2 | Условия: «non-commercial» (вики OSRM), «приложения для трекинга ТС — свой сервис» (Nominatim), «существенная часть предложения» (FOSSGIS) | согласие владельца (§8.3-1); нагрузка минимальна; запасной — ORS (коммерческое на Standard разрешено); при росте — свой VPS |
| R3 | Зимники/сезонность и качество грунтовок не учитываются; время без пробок/погоды; OSRM на дальних перегонах на 0…21 % «пессимистичнее» других сервисов | оценка — подсказка; предупреждение «дороги без названия»; округление вверх; ручное значение всегда главнее |
| R4 | Исходящий HTTP Hostland не проверен | §7 — команда владельцу; при отказе — ручной режим или прокси на VPS |
| R5 | IP сотрудников и область просмотра видны OSM (тайлы напрямую) | согласие владельца; альтернатива — тайл-прокси (OSMF не рекомендует) |
| R6 | Пин на доме — это почти адрес | округление до 3 знаков наружу; полные координаты — только у нас |
| R7 | В поле «населённый пункт» могут ввести адрес/ФИО | валидатор (цифры, запятые, адресные слова, ФИО-форма) + подпись + доступ только `require_edit()`; полностью не исключается |
| R8 | Упаковка: `js/vendor/leaflet/*` и `leaflet.css` не попадут в Hostland-пакет по текущему allowlist | правка `DEPLOY_HOSTLAND.md` в T7/T10 (§1.1) |
| R9 | `.gitignore` не защищает `data/transport_geo.config.php` | добавить строку в T7 |
| R10 | Справочные расстояния — вторичные сайты; Valhalla-выброс (+21,6 %) объяснён выбором другой дороги, не проверялся на карте | при приёмке T7 повторить 3 пары на тех же координатах; сохранить OSRM как основной |
| R11 | Overpass недоступен с этого хоста; ближайший населённый пункт для пина «в поле» внешне получить нельзя | считать локально по известным пунктам (§2.3) |

**Открытые вопросы владельцу** — §8.3 п. 1–6. **Для координатора:** правка `DEPLOY_HOSTLAND.md` (allowlist `js/vendor`, CSS) и `.gitignore` — в T7; отдельной правки `AGENTS.md` эта задача не требует.
