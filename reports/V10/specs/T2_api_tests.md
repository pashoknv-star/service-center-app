## Контекст

Ты пишешь **тесты, а не реализацию**. Реализацию API заявок и назначений (`api/transport_requests.php`, `api/transport_assignments.php`, `api/transport_warnings.php`) делает T5 в следующей фазе другой воркер — и он не вправе править твои тесты. Поэтому контракт `CONTRACT.md` часть 2 — единственный источник правды; если он неоднозначен или противоречит `00_COMMON.md`, `kanban block` с вопросом, а не догадка. Параллельно T1 реализует справочники, пул и перенос ТС (`api/transport_vehicles.php`, схему v15): их фикстуры ты берёшь **по контракту**, реального API T1 в твоём worktree ещё нет. После слияния T1 координатор прогонит твой сьют против реального API; расхождения контракта с реализацией T1 вернутся тебе addendum-задачей.

## Объём

Сьют `transport` в файле `api/transport_test.php`, на временной копии БД через `SC_APP_DB` с поднятым `php -S` (по образцу `api/tasks_links_test.php`: изоляция, свободный порт, sha1 `data/app.db` до/после, «DB intact: YES»). Харнес должен:
- логиниться под `admin`, `supervisor_zone0`, `supervisor_zone1`, `viewer_test` (dev-пароль — как в существующих тестах), отдельная cookie-банка на пользователя;
- создавать фикстуры (базы, ТС, водители группы «Транспорт» и пула, сотрудники бригады, отпуск/болезнь в `schedule_entries`, командировка в `trips`) через API T1 по контракту и, где контракта нет (сотрудники, `schedule_entries`, `trips`), — прямыми SQL на временной БД; данные только синтетические (не «Сотрудник NN»).

Группы проверок (каждая — с положительным и отрицательным случаем):
1. **Права** — вся сводная таблица из `CONTRACT.md`, включая правило `supervisor_zone0` → заявки `supervisor_zone1` и отсутствие обратного права; `can_edit` в GET; viewer 403 на любую запись заявок/назначений; аноним 401; чужие заявки читаются всеми.
2. **Заявки** — создание, поля, `created_by`, `display_no`, правка, `VERSION_CONFLICT`, статусы и переходы (`invalid_transition`), отмена статусом, `DELETE` → 405.
3. **Назначения** — создание, правка, удаление; автоматический `new→assigned` и обратно при удалении последнего; мульти-ТС (несколько назначений у одной заявки); пересчёт `end_at`; переход через полночь; `request_closed`.
4. **Водители и бригада** — допустимый водитель только из группы «Транспорт» ∪ пул (`driver_not_allowed` для остальных); водитель не в бригаде (`driver_in_crew`); бригада — любые сотрудники.
5. **Шаг 15 минут** — `invalid_start`, `invalid_duration`, `invalid_step` для длительности, `stay_min`, `leg_min`; 15/30/45/60 принимаются, 10/20/44 нет.
6. **Предупреждения** — каждый код из `CONTRACT.md` с граничными случаями (касание интервалов — не пересечение; пересечение ТС / водителя / бригады; отпуск, болезнь, командировка; ТС в ремонте; `route_sum_mismatch`); `dry_run` ничего не пишет; `confirm_token`: без токена 409 `confirmation_required`, с токеном другого набора предупреждений — отказ, с верным — запись; предупреждения попадают в журнал.
7. **Журнал** — запись для каждой мутации в той же транзакции (откат мутации откатывает запись; откат по `VERSION_CONFLICT` журнал не засоряет), `before_json`/`after_json`, недоступность правки/удаления (UPDATE/DELETE → ошибка триггера).
8. **Атомарность** — два параллельных запроса на пересекающиеся назначения одного ТС (один `php -S` с несколькими обработчиками или два процесса): либо оба с предупреждением, либо один получает 409 — но пересечение не пропускается молча без `confirm_token`.
