### Как устроена доска

- **Данные:** единственное чтение — `GET api/transport_board.php?from=&to=` (день: `from=to`; неделя: пн–вс). Формат — `T6_REPORT.md` §2. Сьют проверяет, что к API транспорта до переноса обращались только к `transport_board.php`.
- **Время:** строки `YYYY-MM-DDTHH:MM` разбираются как есть (+05); «сегодня» = `Date.now() + 5 ч` в UTC-арифметике, не зависит от пояса браузера. Полоса = `[start_at, end_at)`, обрезанная по границам дня (через полночь — в оба дня, с классами `tp-cont-l/r`).
- **«День» (≥ 720 px):** шкала 24 ч, группа на базу, строка на ТС, дорожки при пересечениях (разный `top`), красная линия «сейчас» для сегодняшнего дня, ремонт — штриховка. **< 720 px:** повестка — карточки по ТС в порядке времени.
- **«Неделя»:** 7 колонок, в ячейке — нагрузка («5 ч · 2 зад.»/«свободно»/«ремонт»), мини-шкала, до 3 чипов (время, №, водитель), «ещё N»; > 9 ч — оранжевая нагрузка; клик по пустому месту ячейки → «День» этой даты; внутренний горизонтальный скролл допустим и используется только внутри `.tp-scroll`.
- **Очередь:** `queue` из ответа (`new` без назначений); карточка: №, название, абонент/адрес, автор (`created_by_name`), «Назначить» при `can_edit`.
- **Карточка:** №, статус, название, абонент, адрес, автор, ТС (+ база), водитель, бригада, время, маршрут (выезд → остановки → приезд с `leg_min`, `leg_km`, стоянками), отметка отсутствия; «Изменить» при `can_edit`.
- **Поллинг** по образцу вкладок: `setInterval` 30 с (`Transport.__t.POLL_MS`), только пока вкладка открыта, панель открыта и `document.hidden === false`; пропуск при открытом диалоге/меню/перетаскивании и во время загрузки; `visibilitychange` → немедленное обновление; при уходе с вкладки таймер снимается.
- **Безопасность вывода:** всё через `createElement` + `textContent`/`setAttribute`; `innerHTML` с данными нигде не используется. Проверено: `<img src=x onerror=…>` в названии, абоненте, адресе — выводится текстом, `window.__xss` не задан, `<img>` в доске нет.

### Как работает перенос ТС

1. Управление есть только при `can_move_vehicle === true` из ответа API (admin, viewer); у supervisor нет ручки ⠿, `draggable`, кнопки «⇄» и подсказки; вызов `Transport.__t.askMove` из консоли у supervisor ничего не отправляет (проверено), сервер всё равно отвечает 403 (проверено).
2. **Перетаскивание:** строка ТС (`.tp-veh`, `draggable`) → группа базы (`.tp-base`, подсветка `tp-drop`; своя база не подсвечивается). **Меню:** кнопка «⇄ Переместить в базу…» → список остальных баз (на сенсорных экранах и клавиатурой; Esc закрывает).
3. Оба пути ведут в диалог подтверждения: «ТС «X» (госномер): «База А» → «База Б»» + подпись **«Перенос постоянный: ТС останется в новой базе, пока его снова не перенесут. Уже созданные назначения не меняются.»** До «Переместить» ничего не отправляется.
4. `POST api/transport_vehicles.php?action=move&id=` `{base_id, version}`; `version` — из загруженной доски. Успех → сообщение «ТС … перенесён в базу … Перенос постоянный.» + перечитывание доски. `409 VERSION_CONFLICT` → «ТС … уже изменён другим пользователем — данные обновлены. Проверьте базу и повторите перенос.» + перечитывание (повтор проходит); 403/401/422/сеть — свои понятные сообщения.
5. Проверено сьютом: БД (`vehicles.base_id`), журнал (`vehicle.move`, +1 на перенос, 0 на отмену и на конфликт), перезагрузка страницы, перенос admin (drag) и viewer (меню), конфликт версий.
