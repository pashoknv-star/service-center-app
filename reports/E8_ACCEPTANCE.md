## Найденные и исправленные дефекты

### Дефект 1 — supervisor не мог подтверждать командировки (`api/trips.php`)
- **Симптом:** `PUT ?action=confirm` возвращал 403 `confirmed_immutable` для supervisor, хотя ТЗ §6/D2 прямо разрешает подтверждение своей зоны.
- **Причина:** гвард `if (!$isAdmin) → 403` внутри confirm-ветки. Зонная проверка по существующим участникам уже выполнена выше (строки 364–384), гвард блокировал только легитимные подтверждения.
- **Фикс:** гвард удалён; зона по-прежнему проверяется до confirm (чужая зона → 403 `zone_forbidden`).
- **Верификация:** sup0 confirm свой forecast → **200**; sup0 confirm чужой (g1) → **403**; sup0 edit confirmed → **403** (read-only по ТЗ); admin edit confirmed → **200**; sup0 delete confirmed → **403**.

### Дефект 2 — viewer не получал обновления (`api/sync.php`)
- **Симптом:** `GET sync.php?afterId=N` → 403 `forbidden` для viewer (read-only). Второй механизм уведомлений по ТЗ §4 — sync-дельта; у viewer она не работала вообще.
- **Причина:** `require_edit()` вызывался для **всех** методов, включая GET, вопреки шапке файла («require_auth, любая роль — чтение»).
- **Фикс:** гвард записи применяется только к POST; GET — `require_auth()`.
- **Верификация (две сессии):** viewer GET дельта → 200; admin создаёт трип → в дельте viewer появляется `tripsChanged` с новым трипом, `lastSyncId` растёт. Toast «Командировки обновлены» показывается из `syncDelta()` (js/trips.js:401) при изменениях чужих трипов.
