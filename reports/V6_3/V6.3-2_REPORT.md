## 1. Что сделано

Одна задача = одна строка Списка и одна плитка Доски, но выполняется в нескольких датах: основная (`start_at`/`end_at`) + повторы. Повтор хранит только дату и время начала и конец; всё остальное (тема, описание, приоритет, метки, исполнители, чек-лист, статус) общее с задачей. «Закрыть» закрывает задачу целиком.

## 2. SQL миграции (v11 → v12)

```sql
CREATE TABLE IF NOT EXISTS task_occurrences (
    id       INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id  TEXT NOT NULL,
    start_at TEXT NOT NULL,
    end_at   TEXT,
    FOREIGN KEY (task_id) REFERENCES tasks(id) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS idx_task_occurrences_task  ON task_occurrences (task_id);
CREATE INDEX IF NOT EXISTS idx_task_occurrences_start ON task_occurrences (start_at);
-- затем meta.schema_version = 12 (делает Database::migrate())
```

Существующие данные не затрагиваются; повторный запуск — no-op.

### Порядок проверки на копии прод-БД перед деплоем

1. Бэкап: `cp data/app.db ~/backups/app.db.pre-v12-$(date +%F)` (на проде — по `DEPLOY_HOSTLAND.md`, раздел 4; `data/app.db` не перезаписывать пакетом).
2. Копия для проверки: `cp data/app.db /tmp/v12_check.db`. Версия до: `sqlite3 /tmp/v12_check.db "select value from meta where key='schema_version';"` (ожидается 11).
3. Прогон миграции на копии (локально, PHP 8.3, не на хостинге): `SC_APP_DB=/tmp/v12_check.db php -r 'require "api/db.php"; $d = Database::getInstance(); $d->migrate(); echo $d->getSchemaVersion();'` → `12`; повторный запуск → `12` (no-op).
4. Проверки: `sqlite3 /tmp/v12_check.db "pragma integrity_check; pragma foreign_key_check; select count(*) from task_occurrences; select count(*) from tasks;"` → `ok`, пусто, `0`, число задач как в проде; сравнить `count(*)` по `tasks`, `task_assignees`, `employees`, `schedule_entries` до и после — не меняются.
5. Прод: выкладка изменённых файлов, первый запрос к API выполняет миграцию; затем `select value from meta where key='schema_version'` → 12, анонимные HTTP-коды, grep-маркеры (`occ_add`, `task_occurrences`).
6. Откат: таблица добавочная — старый код её игнорирует; при откате кода БД оставить как есть (возвращать бэкап не нужно). Но **старый** код (v11) при следующем запуске не понизит версию — выкладывать откат поверх v12-БД безопасно.

Фактически проверено в этой работе: (а) `api/tasks_test.php` M7 — v11→v12 на БД, достроенной до v11: колонки, индексы, FK CASCADE, данные не изменены, второй запуск — no-op; (б) копия dev-БД (`schema_version` 6, 4 сотрудника): миграция 6 → 12, повтор — no-op, `integrity_check: ok`, `foreign_key_check` пусто, сотрудники 4 → 4.

## 3. Отклонения от спеки и решения

1. **Версия задачи при вставке** берётся из загруженной задачи (`S.tasks`); если задача не в текущей выборке (скопировали на одной неделе, вставляют на другой), используется версия на момент «Копировать». Устарела — 409 с понятным сообщением, автоповтора нет (одно действие — один результат).
2. **PUT без `occurrences`** не трогает набор, но пересчитывает концы под новую длительность/сроки; **с `occurrences`** — полная замена (форма всегда его шлёт, пустой список = все повторы удалены).
3. **Код ошибки блока** переименован из заглушки в `TASK_BLOCKED_BY_SICK_OR_TRIP` (422, как в контракте T1); для повтора в ответе есть `occurrence_index` и `message` — форма подсвечивает нужную строку.
4. **Закрытая задача**: повторы остаются (нужны для истории и дат в карточке), отдельно не закрываются; плитки повторов «приглушены» вместе с основной.
5. **Месяц в календаре «Задач» нет** (как в V6.2-2) — вставка в «Месяц» поддержана расчётом `calPasteCalc`, но режима нет.
6. `CODEMAP.md` **не перегенерирован**: параллельно идёт слияние V6.3-1 в тот же `js/tasks.js` — перегенерировать после слияния (`rg --json -n "function |const .*=.*=>" index.html js/storage.js js/tasks.js js/tasks_matrix.js js/trips.js > CODEMAP.md`).
7. `AGENTS.md` (строки с эталонами тестов) не правился (запись заблокирована средой, как в V6.2-2); единственный источник — `BASELINE` в `scripts/verify_all.sh`.
