## Д-1 — повторения
- **Форма задачи:** раздел «Повторения»: «+ Добавить повтор» → дата и время начала; × удаляет. Длительность каждого повтора — как у задачи (для задач без времени — те же дни). Пример владельца: задача 01.01.2027 13:00, повтор 11.01.2027 14:30.
- **Календарь:** каждый повтор — своя плитка со значком ↻; клик открывает ту же карточку. ПКМ «Копировать» по задаче → ПКМ «Вставить» по ячейке теперь **добавляет повтор** этой задачи (новая задача не создаётся). Перетаскивание плитки повтора переносит только этот повтор. ПКМ по плитке повтора → «Удалить повтор».
- **Список и Доска:** задача одна строка / одна плитка. «Срок» — ближайшее предстоящее выполнение (если все прошли — последнее), рядом «↻ N» с перечнем всех дат в подсказке. Сортировка по этому сроку.
- **Карточка:** перечень дат выполнения.
- **Общее для всех повторов:** тема, описание, приоритет, метки, исполнители и наблюдатели, чек-лист, статус. «Закрыть» закрывает задачу целиком.
- **Проверки:** каждый повтор проверяется теми же правилами, что и задача (больничный/командировка исполнителя блокирует, выходной — пометка); значки задач в матрице — на дни всех повторов. n8n-сценарии не меняются (проверка вызывается для каждого повтора).
- **Ограничения:** до 100 повторов, повтор не совпадает по дате и времени с задачей или другим повтором. Править повторы — только admin.

## Самостоятельные решения координатора (вы можете поправить до «Старт»)
1. Статус, чек-лист и исполнители — общие для всех повторов (иначе задача снова «размножится» на Доске).
2. Вставка в календаре всегда добавляет повтор; создание отдельной копии-задачи убирается.
3. Повтор задаётся конкретными датами (как в примере), без правил вида «каждый понедельник».
4. Задачи-копии, уже созданные вставкой на проде, остаются отдельными задачами; автоматически не объединяем.
5. Хранение — новая таблица повторов (миграция БД v12, только добавление). Перед «Деплой» — бэкап и репетиция на копии боевой БД.
