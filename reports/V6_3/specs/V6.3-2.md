# V6.3-2 — Повторяющиеся задачи (Д-1)

Исполнитель: sd_worker_04. Worktree: `/home/hermes/wt/v63-2`, ветка `v63/recurrence`. Сначала — `reports/V6_3/specs/00_COMMON.md`, `REMARKS.md`, `PLAN.md` (раздел «Д-1» и «Самостоятельные решения» — подтверждены владельцем), свой `reports/V6_2/V6.2-2_REPORT.md`.

## Смысл
Одна задача = одна строка в Списке и одна плитка на Доске, но выполняется в нескольких датах: основная дата задачи (`start_at`/`end_at`) + «повторения». Всё остальное у повторов общее: тема, описание, приоритет, метки, исполнители и наблюдатели, чек-лист, статус («Закрыть» закрывает задачу целиком). Повтор задаётся конкретной датой и временем начала (без правил «каждый понедельник»). Пример владельца: задача 01.01.2027 13:00, повтор 11.01.2027 14:30.

## Объём
1. **БД, миграция v12** (`api/db.php`, `api/schema.sql`, `SCHEMA_VERSION` 11 → 12): новая таблица `task_occurrences (id INTEGER PK, task_id TEXT NOT NULL → tasks ON DELETE CASCADE, start_at TEXT NOT NULL, end_at TEXT)` + индексы по `task_id` и `start_at`. Только добавление; существующие данные не меняются. Идемпотентна, тест миграции с v11 на копии dev-БД.
2. **API** (`api/tasks.php`, `api/tasks_rules.php`):
   - Задача в ответе получает `occurrences: [{id, start_at, end_at}]` (по возрастанию) и `next_at` (ближайшее предстоящее выполнение среди основной даты и повторов; если все прошли — последнее). Существующие поля и n8n-контракт не меняются.
   - create/update принимают `occurrences: [{start_at}]` (полная замена набора; конец вычисляется по длительности задачи); точечные действия для календаря: добавить повтор, перенести повтор, удалить повтор — все с `version` задачи (409 при конфликте) и только для admin.
   - Длительность повтора = длительность задачи; для задач без времени — то же число дней. При смене длительности/дат задачи концы повторов пересчитываются. Конец не за 23:59 (правило V6-2).
   - Валидация каждого повтора: формат, ≤ 100 повторов, повтор не совпадает по дате+времени с основной датой и с другим повтором; правила исполнителей (больничный/командировка → блок, выходной → пометка) — теми же функциями, что для задачи (`tasks_check_period_checked`; n8n-сценарии не меняются, проверка вызывается для каждого повтора), ошибка указывает, какой повтор. `conflict` задачи и `tasks_recheck_pending` учитывают повторы. Дни задачи для матрицы (`days[]`/факты `tasks_matrix_facts`) включают дни всех повторов.
3. **Форма задачи** (создание и правка): раздел «Повторения»: «+ Добавить повтор» → дата + время (для задач без времени — дата), × удаляет, список отсортирован; ошибки валидации — у нужной строки.
4. **Календарь:** каждый повтор — отдельная плитка со значком ↻, клик открывает карточку той же задачи. ПКМ «Копировать» по плитке (задачи или повтора) → ПКМ «Вставить» по ячейке **добавляет повтор** этой задачи (новая задача не создаётся; пункт меню — «Вставить повтор»; сообщение «Повтор добавлен на ДД.ММ ЧЧ:ММ · Открыть»). Перетаскивание плитки повтора переносит только этот повтор; плитки основной даты — как сейчас (W-5). ПКМ по плитке повтора → «Удалить повтор» (с подтверждением). Создание отдельной копии-задачи вставкой убирается. Ограничение V6.2: копировать задачу без исполнителя нельзя — теперь не нужно (повтор не создаёт задачу), снять.
5. **Список и Доска:** одна строка/плитка; «Срок» — `next_at`, рядом «↻ N» (N = число повторов), в подсказке все даты выполнения; сортировка по сроку — по `next_at`. **Карточка:** перечень всех дат выполнения.
6. **Матрица** (`js/tasks_matrix.js`): иконки задачи на днях всех повторов.
