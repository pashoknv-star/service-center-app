**Сервер (`api/tasks.php`)**
- `TASKS_LABEL_MAX` 50 → **200** (`:45`), новая `TASKS_LABEL_TAG_MAX = 30`.
- `tasks_label_tags()` (`:411`) — split по «,», trim, схлопывание пробелов (`\s+`/u), без пустых и дублей без учёта регистра (`mb_strtolower`, первая форма побеждает). `tasks_norm_label()` (`:433`) — используется в create (`POST`) и update (`PUT`), хранит `"тег1, тег2"`, пусто → `NULL`; ошибки `400 invalid_label` + понятный `message` (тег > 30, строка > 200, не строка).
- В ответе задачи (`:263`) добавлен `labels: [...]` (читается из сохранённой строки, поэтому старые значения вида `a,b` без миграции отдаются несколькими тегами); строковое `label` сохранено (n8n, `tasksn8n` 25/25).

**Клиент (`js/tasks.js`)**
- `splitTags/tagsOf/labelsOf/hasTag` (`:283–307`): та же нормализация, что на сервере; `labelsOf` — уникальные теги без учёта регистра, по алфавиту; фильтр «Метка» (`applyFilters`, `:326`) — «задача содержит тег» (без учёта регистра).
- Отображение: `badgesHtml` (`:369`) — каждый тег отдельный чип `tk-tag tk-tagbtn tk-ltag` (`filterBy`, R-12: клик → «Список» с одним фильтром по тегу) в Списке (теперь со ссылками — раньше метка в строке Списка была не кликабельной), на Доске и в карточке.
