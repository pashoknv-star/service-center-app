Исполнитель: sd_worker_03. Worktree: `/home/hermes/wt/v62-1`, ветка `v62/list-tags`. Сначала — `reports/V6_2/specs/00_COMMON.md`, `REMARKS.md`, `PLAN.md`.

## Объём
1. **W-1 Список, колонки.** Порядок: Задача · **Описание** · **Исполнитель** · Срок · Приор. · Статус (+ колонка W-2). Ширина «Исполнителя» — половина нынешней: замерить фактическую ширину колонки на 1280 до правки (в отчёт) и задать ~50 % от неё; «Описание» забирает освободившееся. ФИО переносятся, «!» (R-8) и клик-фильтр (R-14) сохраняются. 375px: таблица по-прежнему прокручивается горизонтально, шапка sticky.
2. **W-2 «Править» в строке Списка.** Последняя узкая колонка без заголовка-текста (доступное имя «Править»): кнопка ✎ с `title="Править"` → сразу форма правки этой задачи (тот же путь, что «Править» в карточке). Клик по кнопке не открывает карточку (stopPropagation), клик по строке — как раньше. Только `canWrite()`; у supervisor/viewer колонки нет. Клавиатура: Enter/Space.
3. **W-3 Доска.** В плитке не больше 2 исполнителей; при >2 после второго «…»; полный список ФИО — в `title` подстроки. Первые два ФИО кликабельны (V6-5, `filterEmp`), зачёркивание удалённых сохраняется. Карточка задачи и Список — без изменений (там все исполнители).
4. **W-4 Метки-теги.**
   - Хранение: `tasks.label` (TEXT) — теги через запятую. Сервер (`api/tasks.php`, create и update) нормализует: split по запятой, trim, схлопнуть пробелы, убрать пустые и дубли (без учёта регистра, первая форма побеждает), каждый тег ≤ 30 символов, вся строка ≤ 200 (`TASKS_LABEL_MAX` 50 → 200); сохраняется `"тег1, тег2"`; пусто → NULL. Ошибки — понятным текстом (`invalid_label`). Ответ API дополнительно отдаёт `labels: [...]`; строковое `label` остаётся (n8n, `tasks_n8n` не ломать).
   - Форма правки/создания: поле-теги — ввод, Enter или запятая → чип; × на чипе удаляет; Backspace в пустом вводе удаляет последний; подсказки из существующих тегов (`datalist` или свой список); вставка строки с запятыми → несколько чипов. При сохранении введённый, но не превращённый в чип текст тоже сохраняется как тег.
   - Отображение: в Списке, на Доске и в карточке каждый тег — отдельный кликабельный чип (R-12: клик → Список с фильтром по этому тегу).
   - Фильтр «Метка» в Списке: варианты — отдельные теги (уникальные, по алфавиту), совпадение — задача содержит тег.
   - Старые значения с запятой (на проде такие есть — 2 задачи) после выкладки показываются как несколько тегов — это принято владельцем; миграции нет.
