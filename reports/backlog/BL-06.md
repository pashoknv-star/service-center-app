# BL-06 — Удаление сотрудника в первые ~15–20 с после загрузки страницы молча откатывается (N-1 из T1-10)

**Статус:** бэклог. **Решение владельца (2026-11-11):** вариант (в) — отложить. Не запускать без явной команды владельца.

## Суть
Найдено независимой приёмкой T1-10 (`reports/TASKS_BLOCK/T1-10_ACCEPTANCE.md`, наблюдение N-1, воспроизведено: audit id 5924/5925 в копии БД).
Admin удаляет сотрудника вскоре после загрузки страницы → стартовый `save()` страницы сдвигает `sync_log`, курсор клиента отстаёт →
сервер блокирует удаление защитой E10-6 (`api/save.php:356–376`, audit `sync.stale_delete_blocked`) → сотрудник возвращается.
Пользователь не видит ни сообщения, ни (с T1-8) окна замены, хотя только что подтвердил «Открытых задач: N — останутся без исполнителя».

Не регрессия блока «Задачи»: защита E10-6 старше T1. С T1-8 стала заметнее.

## Варианты (предложены владельцу 2026-11-11)
- (а) сообщение «Удаление не применено, повторите» при `sync.stale_delete_blocked` — малая правка UI + признак в ответе `save.php`;
- (б) устранить причину: почему стартовый `save()` сдвигает `sync_log` раньше, чем клиент получает курсор (затрагивает синхронизацию E8/E10);
- (в) отложить — **выбрано**.
