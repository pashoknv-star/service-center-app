# T1-4 n8n: детерминированные правила задач (webhook + расписание)
Прочитать `00_COMMON.md`, TZ §3. Зависит: T1-1 принят (эталон правил в `api/tasks_rules.php`, `calendar_facts`).

PRECONDITION: в окружении есть `N8N_API_KEY` (владелец выдаёт; значение НЕ печатать, не логировать, не писать в файлы). Если ключа нет — `kanban block "нет N8N_API_KEY"` и остановиться. Базовый URL: `https://n8n.domenforjob.ru` (REST `/api/v1`). Сервис-токен приложения для `calendar_facts` — из окружения/конфига приложения, не из чата.

Objective: workflow в n8n, исполняющие детерминированные правила (БЕЗ LLM).

Требования:
1. Workflow `tasks-validate` (webhook, POST): вход {employee_ids[], from, to} → запрашивает `calendar_facts` приложения → возвращает {blocked_days[], notes[], suggested_start}. Логика строго эквивалентна `tasks_rules.php` (sick/trip блок; выходной/праздник/отпуск — notes). Webhook защищён заголовком-секретом; ответ ≤ 3 с.
2. Workflow `tasks-recheck` (расписание, раз в 15 мин): пересчитывает задачи с `check_state='pending'` и выставляет признак `conflict` для открытых задач, попавших на новый больничный/командировку; запись — только через защищённые эндпойнты приложения.
3. Если нужны доп. эндпойнты приложения (пакетная перепроверка, установка `check_state`) — их добавляет ЭТА задача минимально в `api/tasks.php` (согласовать, не ломая контракт T1-1) с тестами.
4. Workflow создаются через REST API n8n; JSON-экспорты сохранить в `n8n/` репозитория БЕЗ credentials. Перепроверить через MCP n8n (`search_workflows`/`get_workflow_details`).
5. Нагрузочный/функциональный прогон: набор кейсов (выходной, праздник, отпуск → допустимо; sick, trip → блок; частичное пересечение периода; несколько исполнителей) — результат n8n сравнить с PHP-эталоном, расхождений 0.
6. Подключение приложения к webhook (вариант B): `api/tasks.php` вызывает `tasks-validate` с таймаутом 3 с; при недоступности — PHP-fallback + `check_state='pending'` (допущение Д-3). Настройка URL/секрета — через `meta`/конфиг, не в коде.

Acceptance: AC-3, AC-4, AC-8; отчёт содержит фактические вызовы и ответы (без секретов), таблицу сверки n8n vs PHP; `verify_all.sh` → GATE: PASS.
