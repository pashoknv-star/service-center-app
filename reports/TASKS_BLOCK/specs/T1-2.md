# T1-2 Панель «Задачи»: Список / Доска / Календарь (frontend)
Прочитать `00_COMMON.md`, TZ §4, `mockups.html` (разделы 2.1–2.3). Зависит: T1-1 принят (api/tasks.php работает).

Objective: панель «Задачи» со всеми тремя видами и ролевым доступом.

Scope: новый `js/tasks.js` (+ `css` внутри модуля или отдельный блок) — основная реализация; в `index.html` ТОЛЬКО точечные вставки: подключение скрипта, кнопка/вкладка «Задачи», контейнер панели (anchor-вставки с номерами строк, по образцу интеграции `js/trips.js`). Out of scope: иконка и рамка в матрице (T1-3), n8n, LLM.

Требования:
1. Вид по умолчанию «Список» (таблица: задача, исполнитель(и), срок, приоритет, статус; фильтры: сотрудник, срок, приоритет, метка, статус). Клик по фамилии → «Доска», отфильтрованная по сотруднику; клик по задаче → «Доска» с выделенной карточкой. Переключатель Список | Доска | Календарь.
2. «Доска»: колонки «Открыта» / «Закрыта». Перенос карточки в «Закрыта»/обратно — только admin.
3. «Календарь» (неделя/день, как Outlook): ВСЕ задачи всех сотрудников; плитка = ФИО + описание (обрезка с «…»); клик по плитке — карточка справа (описание, чек-лист, приоритет, метка, исполнители, пометки конфликта/«не проверено»). Поддержать вход «открыть на сотруднике и дате» (`openTasksPanel({employeeId, date, view:'calendar'})` — для T1-3).
4. admin: создать/править/переназначить/закрыть/переоткрыть/архивировать (форма: название, описание, исполнители 1..N, срок ИЛИ период с датой и временем, приоритет 1..3, метка, чек-лист; поле «наблюдатель» хранится, но скрыто/неактивно). При 422 `TASK_BLOCKED_BY_SICK_OR_TRIP` показать заблокированные дни и кнопку «Принять предложенную дату» (`suggested_start`), решение подтверждает admin. Пометки выходной/праздник/отпуск — нейтральные, без запретов.
5. supervisor/viewer: все элементы записи не рендерятся, API всё равно вернёт 403 (проверить).
6. 409 `VERSION_CONFLICT` → понятное сообщение и перезагрузка карточки, данные не затираются.
7. Не ломать mobile compact (P13), не менять sync/save-логику. Экспортируемые обработчики (inline onclick) — только через `window.Tasks.*` и каждый проверить grep'ом на существование (урок 4× мёртвых кнопок).

Acceptance: AC-1, AC-8(UI-пометка), панель работает под admin/supervisor/viewer; извлечённый inline-`<script>` проходит `node --check`; `scripts/check_syntax.js` failed: 0; добавлен frontend-сьют (по образцу `scripts/test_trips_frontend.sh`) и поднят BASELINE; `verify_all.sh` → GATE: PASS; ручной/headless e2e: создать → список → клик по фамилии → доска → календарь → закрыть.
