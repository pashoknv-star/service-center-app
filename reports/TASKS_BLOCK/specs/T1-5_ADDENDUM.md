# T1-5 ADDENDUM (2026-11-07, координатор)

## 1. Провайдер LLM (решение владельца)
- Вариант «модель профиля sd_worker_04» ОТМЕНЁН владельцем: для функций отслеживания задач используется отдельный API модели.
- Провайдер, модель и ключ владелец добавит в `/etc/service-center-app/secrets.env`.
  Ожидаемые имена: `LLM_API_KEY`, `LLM_BASE_URL` (OpenAI-совместимый endpoint), `LLM_MODEL`. Если имена другие — взять фактические, перечислить в отчёте.
- Загрузка только в окружение своих команд (`set -a; . /etc/service-center-app/secrets.env; set +a`), значения не печатать.
- В n8n ключ заводится как credential через `POST /api/v1/credentials`; все 4 workflow берут модель из одного параметра,
  чтобы смена провайдера не требовала переделки workflow.
- Если на момент старта переменных LLM нет — `kanban block "нет LLM_API_KEY"`, complete не вызывать.

## 2. Топология (как в T1-4_ADDENDUM)
n8n не вызывает приложение. Приложение само собирает детерминированные данные (allowlist полей) и отправляет их
в webhook `llm-*` по HTTPS с header-auth секретом; ответ валидируется по JSON-схеме на стороне приложения, запись — только после «Применить».
Ключ n8n — `N8N_API_KEY` из того же файла.
