# T1-8 D-1 UI: отображение «Исполнитель удалён» + окно замены после удаления сотрудника
Прочитать `00_COMMON.md`, `T1-2_REPORT.md`, `T1-7_REPORT.md` (контракт: `assignees[].removed`, `orphan`, `removed_at`, `?orphans=1`, `?open_for=`). Зависит: T1-7 принят. Исполнитель — автор T1-2/T1-3.

## Решение владельца (2026-11-10, утверждено по предложению координатора)
| Где | Что |
|---|---|
| Вкладка «Задачи» | оранжевый счётчик «⚠ N» — открытые задачи без исполнителя (`?orphans=1`); 0 → счётчика нет |
| Список | в колонке «Исполнитель» серая плашка «Исполнитель удалён (Иванов И.И.)», оранжевая полоса слева у строки; в фильтре пункт «Без исполнителя» |
| Доска | отдельная секция «Без исполнителя» сверху |
| Календарь | плитка с пунктирной оранжевой рамкой и подписью «без исполнителя» |
| Карточка | плашка «Исполнитель удалён <дата removed_at>» + кнопка «Назначить» (admin); закрыть можно без исполнителя |
| 2 исполнителя, удалён один | задача не «без исполнителя»; удалённый в карточке зачёркнут |
| Закрытые задачи | без пометок; ФИО (snapshot) остаётся |

Окно замены — только при удалении admin через кнопку «Удалить сотрудника» (`index.html` ~4367, обработчик `#deleteEmp`):
1. Перед `confirm` запросить `?open_for=<id>`; при N>0 текст подтверждения дополняется строкой «Открытых задач: N — останутся без исполнителя.» (если запрос не удался — исходный текст, удаление не блокировать).
2. После удаления (после `save()`) при N>0 — модальное окно «У <ФИО> было N открытых задач»: список задач с галочками (все отмечены), «Передать: [сотрудник ▾]» (действующие сотрудники), кнопки «Назначить» и «Позже».
3. «Назначить» — PUT по каждой отмеченной задаче (с `version`). 422 sick/trip — задача не переназначается; в окне у неё причина и кнопка «Принять предложенную дату» (как в форме задачи); остальные переназначаются. 409 — перечитать задачу и повторить один раз, иначе показать ошибку у этой задачи.
4. «Позже» — закрыть окно; задачи остаются в счётчике ⚠.
5. Удаление через sync/импорт окна не показывает — видно по счётчику.
6. supervisor/viewer видят все пометки, но не видят «Назначить» и окно (кнопка удаления у них и так скрыта).
После переназначения — событие `tasks:changed` (матрица и счётчик обновляются).

## Реализация
Логику и окно — в `js/tasks.js` (экспорт, например, `window.Tasks.offerReassign(empId, fullName, tasks)` и `window.Tasks.openTasksFor(empId)`); в `index.html` — только точечная правка обработчика `#deleteEmp` (anchor по строке, не читать файл целиком). Стили — рядом с существующими стилями задач. Без LLM-элементов.
Каждый новый `data-tk-act` — с обработчиком в `ACTIONS`; каждый `window.Tasks.*`, вызываемый из `index.html`, — экспортирован (частый дефект прошлых фаз).

## Тесты (`tasksui`, поднять BASELINE)
Плашка/полоса/фильтр в Списке, секция Доски, плитка Календаря, карточка и «Назначить», счётчик (0 → нет; N), частичное удаление (зачёркнут, не orphan), закрытая задача без пометок; окно: текст confirm с N, назначение, 422 с «Принять предложенную дату», «Позже»; роли viewer/supervisor — без «Назначить». Плюс ручная проверка в реальном браузере (скриншоты в `reports/TASKS_BLOCK/T1-8_screens/`): удаление сотрудника с 2 открытыми задачами → окно → одна назначена, у второй 422 → «Позже» → счётчик ⚠ 1.
