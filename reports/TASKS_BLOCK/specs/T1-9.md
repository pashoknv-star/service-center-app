## D-4 (`api/tasks_rules.php`, тесты в `api/tasks_n8n_test.php`)
1. `tasks-validate` (синхронно, пользователь ждёт): таймаут 3000 мс — без изменений.
2. `tasks-recheck` (после ответа пользователю, `tasks_send_json_then`): таймаут 10000 мс — отдельная константа.
3. Каждый вызов n8n меряет длительность. Вызов, не завершившийся за 10 с (для recheck — его таймаут), пишется в `error_log` одной строкой с маркером `tasks n8n ANOMALY` (workflow, мс, reason; без секрета, без payload). Таймаут validate за 3 с — штатная ситуация (pending), не аномалия, но тоже логируется отдельным маркером без «ANOMALY».
4. Тесты на mock-webhook (как в существующем сьюте, без сети): validate с задержкой 4 с → pending ≤ ~3,5 с; recheck с задержкой 4 с → успех (pending→ok); recheck сверх таймаута → строка `ANOMALY` в логе. Чтобы не удлинять сьют на 10+ с, таймаут recheck в тесте можно передать параметром функции (продовое значение — константа 10000, проверяется отдельным assert). Поднять BASELINE `tasksn8n`.
