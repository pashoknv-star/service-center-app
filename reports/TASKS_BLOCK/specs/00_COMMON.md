# T1 «Блок Задачи» — общие правила для всех задач

Источники (обязательно прочитать): `reports/TASKS_BLOCK/BFT.md` v1.0 (утверждён), `reports/TASKS_BLOCK/TZ.md` v0.2 (утверждено 2026-11-07), `reports/TASKS_BLOCK/mockups.html`, `AGENTS.md`, `PROGRESS.md`. Решения владельца в БФТ/ТЗ связывающие — не переосмысливать.

## Зафиксированные решения владельца (дословно)
- MVP: блок «Задачи» меняет только admin; supervisor и viewer видят иконку в календаре и открывают задачу в панели «Задачи» (только чтение).
- Статусы только «открыта» / «закрыта»; закрывает только admin.
- Иконка в ячейке матрицы — вариант B (круг со счётчиком) только на ПЕРВОМ дне срока открытой задачи; весь срок выделен тонкой рамкой по образцу обрамления фото сотрудника.
- Задача МОЖЕТ охватывать выходные/праздники/отпуск; НЕ МОЖЕТ охватывать больничный/командировку (каждый день периода, по каждому исполнителю).
- Основной вид панели — «Список» (2.2); клик по фамилии или задаче → «Доска» (2.1); переключатель на «Календарь» (2.3) показывает ВСЕ задачи всех сотрудников, в плитке ФИО и описание. Клик по иконке в матрице → вид «Календарь» на неделе с этим днём.
- n8n: правила через webhook (вариант B). LLM только предлагает, запись в БД только после подтверждения человека; LLM видит фамилии и тексты задач, НЕ видит телефоны/фото/пароли/токены.

## Правила проекта
- Отдельный `api/tasks.php`; НЕ расширять sync-delete `save.php`. Новый код — в новых файлах; правки `index.html` (монолит ~1 МБ) только точечные, anchor-вставки с номерами строк. Не читать index.html целиком.
- Gate: `bash scripts/verify_all.sh` → `GATE: PASS`; при добавлении тестов поднять `BASELINE`. `git status --porcelain` — только файлы задачи; `data/app.db` вернуть `git checkout -- data/app.db`. Обновить PROGRESS.md (Current State), закоммитить. Пуш в main — только координатор.
- Деплой на Hostland запрещён. Никаких секретов в файлах, логах, отчётах, коммитах (ключи n8n/LLM — только из окружения/vault).
- Отчёт в `reports/TASKS_BLOCK/<ID>_REPORT.md`: что реализовано (не план), команды проверки и их фактический вывод, список изменённых файлов. Без вывода прогона задача не закрывается. Не выдумывать результаты и инструменты проверки.
- При блокирующей проблеме (429/баланс/контекст, отсутствует ключ) — `kanban block` с причиной, а не complete.
- Старт работ только после «Старт» владельца.
