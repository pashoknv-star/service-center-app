# T1-1 Миграция БД v7 + api/tasks.php + тесты (backend)
Прочитать `00_COMMON.md`, TZ §1–3.

Objective: серверное ядро блока «Задачи».

Scope (пути): `api/schema.sql`/миграция по текущему механизму (см. `api/init_db.php`, `api/db.php`, как сделана v6 для trips), новый `api/tasks.php`, функции правил в новом `api/tasks_rules.php`, тесты в `api/smoke_test.php` или новом сьюте + `scripts/verify_all.sh` BASELINE. Out of scope: index.html, js/, n8n, LLM.

Требования:
1. Таблицы по TZ §1: `tasks`, `task_assignees` (роль assignee|watcher), `task_checklist`; индексы; миграция идемпотентна, существующие данные не трогает; schema version 7.
2. Эндпойнты по TZ §2: GET список (`from`,`to`,`employee_id`; без employee_id — все задачи диапазона), GET по id, POST создать, PUT править/переназначать (с `version`), POST `action=close|reopen`, DELETE = архив (`archived=1`). Запись — только admin; supervisor/viewer — 403 на любую запись; чтение — все авторизованные. Анонимно — 401.
3. Вычисляемые поля в GET: `first_day`, `days[]`, `conflict` (открытая задача, один из дней исполнителя — sick/trip), `notes` (выходной/праздник/отпуск — нейтральные пометки). Источники: `schedule_entries`, `trips`+`trip_participants`, `holidays` (+ `data/holidays/*.json` через существующий `holidays_provider`).
4. Проверка FR-10 при POST/PUT: любой день периода у любого исполнителя на sick/trip → 422 `TASK_BLOCKED_BY_SICK_OR_TRIP` с `blocked_days` и `suggested_start`. Реализовать как PHP-функцию в `tasks_rules.php` (используется как fallback и как источник эталонной логики для n8n в T1-4). Вызов n8n webhook в этой задаче НЕ делать, но предусмотреть поле `check_state` (`ok|pending`) и точку расширения.
5. Эндпойнт `GET ?calendar_facts&employee_id&from&to` — защищённый сервисным токеном (по образцу `external_api_token`; значение не выводить) — возвращает по дням: статус матрицы, выходной/праздник, trip.
6. Ответы без телефонов/фото. 409 `VERSION_CONFLICT` при устаревшем `version`. Все мутации → `audit_log`.
7. Не менять поведение save.php/load.php/trips.php (регрессия по существующим сьютам).

Acceptance: AC-1(API-часть), AC-3, AC-4, AC-5, AC-7 из TZ §6; тесты на каждый пункт 2–6 (в т.ч. RBAC-матрица admin/supervisor/viewer/anon curl), BASELINE повышен, `verify_all.sh` → GATE: PASS.
Artifacts: код, тесты, `reports/TASKS_BLOCK/T1-1_REPORT.md`, коммит. Verification: полный вывод `verify_all.sh`.
