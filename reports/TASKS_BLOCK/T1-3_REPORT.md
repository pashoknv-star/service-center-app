## Итог

Новый модуль `js/tasks_matrix.js` (320 строк, ES5-IIFE, `window.TasksMatrix`) красит матрицу отпусков после каждого
`renderVacationMatrix()` (обёртка — тот же приём, что overlay в `js/trips.js`):

- **Иконка варианта B** — круг `#0088CC` со счётчиком ОТКРЫТЫХ задач, СТАРТУЮЩИХ в этот день у этого сотрудника;
  `#F44336`, если у любой из них `conflict`; счётчик ≥10 → «9+». Только на ПЕРВОМ дне срока. Закрытая и архивная — без иконки.
- **Рамка срока** — на всех ячейках периода (включая выходные/отпуск/больничный): `1.5px solid var(--rt-blue)`, radius 8
  на концах, свечение `0 0 6px rgba(0,136,204,.2)`, без заливки. Реализована как `::before` ячейки (`pointer-events:none`),
  поэтому классы статусов (`type-vacation`, `type-sick`, `day-weekend`…) и обработчики ячеек не затрагиваются.
  Пересекающиеся сроки одного сотрудника сливаются в одну рамку, смежные — отдельные рамки со своими краями.
  Срок, выходящий за границу года, рисуется без «скобки» на стороне продолжения; иконка — только если первый день в показанном году.
- **Клик по иконке** → `openTasksPanel({employeeId:'emp_N', date:'YYYY-MM-DD', view:'calendar'})`, всем ролям
  (в модуле нет проверок роли; запись закрыта на API). Перехват — один capture-обработчик на `#matrixBody` (click, mousedown).
  Ctrl/Meta/Shift+клик, правая кнопка и пик-режим командировок (`window._employeePickActive`, `Trips.suppressInfoPanel()`)
  НЕ перехватываются — событие идёт в ячейку, как раньше.
- **Данные** — один `GET api/tasks.php?from=YYYY-01-01&to=YYYY-12-31` на показанный год, кеш по году, дедупликация запросов,
  устаревший ответ (запрос начат до мутации) отбрасывается. Обновление: `js/tasks.js` после успешной записи (и после 409)
  шлёт `document` событие `tasks:changed`; если матрица скрыта (открыта панель «Задачи») — перезагрузка откладывается
  до её показа. После входа (`#authOverlay` → `hidden`) данные загружаются заново (запрос до входа получает 401).
  Модуль ТОЛЬКО читает: ни `save.php`, ни `Storage`, ни POST/PUT/DELETE (проверяется тестом A7).

## Отклонения / допущения (подтвердить при приёмке)

1. **Рамка только у ОТКРЫТЫХ задач.** ТЗ §4.2 связывает иконку и рамку с открытой задачей; AC-2: «закрытая задача иконки не имеет». Закрытая/архивная
   задача не рисует и рамку (рамка — признак «есть что делать»). Если нужна рамка и у закрытых — это правка одной строки фильтра в `buildPlan`.
2. **Рамка рисуется поверх верхней кромки «праздничной» отметки** (`.day-holiday::after`, `border-top:3px`): синяя линия 1.5px перекрывает верхние 1.5px красной
   праздничной полоски; заливки статусов и сами цвета не затрагиваются. Рамка сделана `z-index:2`, чтобы не прерываться на праздниках.
3. **Правка тестового харнесса T1-2** (`scripts/test_tasks_frontend.js`, 87–96, вне scope T1-3): на текущем состоянии хоста сьют tasksui стабильно падал
   (E6, затем E-FATAL) уже на HEAD `6aadaee` (проверено в чистом worktree) — `settle()` считал запрос завершённым по заголовкам, а `php -S` под нагрузкой отдаёт
   тело ответа с задержкой. Теперь «в полёте» снимается после чтения тела. Проверок не добавлено/не убрано (63/63), логика проверок не менялась.
4. **`tasks:changed`** — новая точка связи `js/tasks.js` → матрица (11 строк в tasks.js). Альтернатива без правки tasks.js (перезагрузка при каждом показе матрицы)
   дороже; выбрано событие + отложенная перезагрузка.
5. **AGENTS.md** (защищённый, строка с `BASELINE`) не менялась: источник правды — `BASELINE` в `scripts/verify_all.sh` (добавлен `tasksmx=70`). Координатору — добавить в AGENTS.md.
