## Итог

Панель «Задачи» реализована как отдельный модуль `js/tasks.js` (1089 строк, ES5-IIFE по образцу `js/trips.js`)
и подключена к существующей панели отпусков третьей вкладкой «Задачи» (после «Матрица отпусков» и «Командировки»).
`bash scripts/verify_all.sh` → `GATE: PASS (10 suites)`, новый сьют `tasksui` 63/63.

**Проверялось без браузера.** На хосте нет Chrome/CDP, а удалённый браузер недоступен (`CDP WS handshake failed`).
Поэтому e2e выполнен в Node: `js/tasks.js` исполняется в `vm` с минимальным DOM-шимом и ходит по HTTP в настоящий
`api/tasks.php` (временный `php -S` на копии БД). Проверены разметка (строка HTML), логика и запросы.
**Визуальная вёрстка (CSS, сетка календаря, mobile compact) в реальном браузере НЕ просматривалась** —
рекомендую быстрый ручной просмотр владельцем/приёмкой (T1-6) на десктопе и в узком окне.

## Что реализовано (по требованиям)

1. **Список** (вид по умолчанию): таблица Задача / Исполнитель / Срок / Приор. / Статус; фильтры: сотрудник, срок
   (сегодня / на этой неделе / просрочено), приоритет, метка, статус + «Сбросить». ФИО исполнителей — ссылки:
   клик → «Доска» с фильтром по сотруднику. Клик по строке задачи → «Доска» с выделенной карточкой (`tk-sel`) и
   карточкой справа. Переключатель Список | Доска | Календарь.
2. **Доска**: колонки «Открыта · N» / «Закрыта · N». Закрыть/переоткрыть перетаскиванием (только admin; у
   supervisor/viewer `draggable` не рендерится, обработчики drop/dragstart закрыты проверкой роли) и кнопками в карточке.
3. **Календарь** (неделя/день, ◀ ▶ «Сегодня»): ВСЕ задачи всех сотрудников за видимый период (запрос
   `?from&to`); плитка = ФИО исполнителей + описание (обрезка с «…»: 48 симв. в неделе, 140 в дне); многодневные —
   «09:00 →», «…продолжение», «→ 18:00»; клик по плитке — карточка справа (описание, чек-лист, приоритет, метка,
   исполнители, пометки конфликта / «не проверено»). Селектор сотрудника подсвечивает его плитки, чекбокс «только
   выбранный» — фильтр «все/сотрудник». Вход для T1-3: `window.openTasksPanel({employeeId, date, view:'calendar', taskId?, mode?})`
   (= `window.Tasks.open`): открывает панель отпусков, вкладку «Задачи», неделю с этим днём; `employeeId` принимает
   `emp_2` и `2`.
4. **admin**: создать / править / переназначить / закрыть / переоткрыть / в архив (с `confirm`). Форма: название,
   описание, исполнители 1..N, срок (один день) ИЛИ период с датой и временем, приоритет 1..3, метка (datalist
   существующих), чек-лист (добавить/удалить/отметить). «Наблюдатель» — отключённый `<select>` (значение хранится
   на сервере, UI его не отправляет и не меняет). При 422 `TASK_BLOCKED_BY_SICK_OR_TRIP` форма остаётся открытой,
   показываются заблокированные дни (дата — ФИО — больничный/командировка) и кнопка «Принять предложенную дату»
   (`suggested_start`/`suggested_end`); задача НЕ создаётся, пока admin не нажмёт кнопку (нажатие = подтверждение,
   после него форма сразу сохраняется на предложенный срок). Пометки выходной/праздник/отпуск/отгул — нейтральные
   серые, справочные, без запретов.
5. **supervisor / viewer**: бейдж «только просмотр»; кнопки «+ Новая задача», «Править», «Переназначить», «Закрыть»,
   «Переоткрыть», «В архив», форма, `draggable` не рендерятся (тест R-*-2/3). Принудительный вызов обработчиков
   записи ничего не отправляет (R-*-4); прямой API на POST/PUT/close/reopen/DELETE → 403, данные не меняются (R-*-5).
6. **409 VERSION_CONFLICT**: понятное сообщение («Задача уже изменена другим пользователем (актуальная версия N)…
   ваши правки не применены»), форма закрывается, карточка перезагружается из ответа/сервера (из «Списка» — переход
   на «Доску» с этой карточкой). Данные другой вкладки не затираются (тест E34).
7. **Не ломаем остальное**: новый код — только в `js/tasks.js`; `index.html` — 3 точечные вставки (ниже); sync/save
   не трогались; mobile compact: `@media (max-width:760px)` — колонки и карточка в столбик, календарь с горизонтальным
   скроллом; уход на другие вкладки — клики по `#tabMatrix`/`#tabTrips` + MutationObserver на `#matrixWrapper` и
   `#tripsListView` (`Trips.switchTab` вызывается и программно изнутри `trips.js`).
8. **Обработчики**: ни одного inline `onclick`/`onsubmit`. Все кнопки несут `data-tk-act="<имя>"`, имена разрешаются
   через таблицу `ACTIONS` (делегирование на `#tasksView`); тест S1 проверяет, что каждое из 22 имён `data-tk-act`
   в исходнике имеет обработчик (урок «4× мёртвых кнопок»). Публичный интерфейс — только `window.Tasks.*` и
   `window.openTasksPanel`; из `index.html` обращений к `Tasks.*` нет (S4).

## Принятые решения (не из ТЗ — подтвердить при приёмке)

- Приоритет: 1 = высокий, 2 = обычный (по умолчанию, как в API), 3 = низкий; «высокий» выделяется оранжевым.
- Фильтр «сотрудник» общий для «Списка» и «Доски» (клик по фамилии выставляет именно его). Фильтры срока/приоритета/
  метки/статуса — только в «Списке».
- Роль берётся из `api/session.php` при каждом открытии вкладки (а не из глобалов страницы): после смены учётки права
  пересчитываются.
- Список сотрудников для фильтров/формы — `api/employees.php` (GET, любой авторизованный; в памяти панели хранятся
  только `id` и `full_name`). В `window.__serverEmployees` id приведены к числам, поэтому он не используется.
- Календарь показывает 7 дней недели (а не 5 как в макете): задача может охватывать выходные.
- В календаре и в «пометках» карточки выходной/праздник/отпуск/отгул — нейтральные (серый тег), не красные.
- Архивная задача после «В архив» исчезает из панели; на сервере остаётся (читается по id).
- Чек-лист в карточке — только чтение (по ТЗ отметка пунктов — через форму admin).
