Обновляется: при старте модуля, при открытии панели отпусков (`#vacationTrigger`), при открытии вкладки, после любой записи (`tasks:changed`), после удаления сотрудника, при закрытии окна замены |

| 2 исполнителя, удалён один | задача не orphan: нет плашки/полосы/секции; удалённый зачёркнут (`<s class="tk-gone">`) в списке и карточке |

**Окно замены** (`window.Tasks.openTasksFor(empId)` до удаления, `window.Tasks.offerReassign(empId, fullName, tasks)` после; в `index.html` правка только обработчика `#deleteEmp`):
1. До `confirm`: `?open_for=<id>` (таймаут 5 с); при N>0 текст дополняется «Открытых задач: N — останутся без исполнителя.»; сбой/таймаут/исключение → исходный текст, удаление не блокируется.
2. После `await save()` при N>0 и подтверждённом сохранении (`success !== false`, не `fallback`/`localOnly`) → `offerReassign`. Окно не показывается, если справочник после перечитывания всё ещё содержит сотрудника (сервер не применил удаление — stale-защита `save.php`) и для не-admin (роль перечитывается из `api/session.php`). Удаление через sync/импорт окна не вызывает — видно по счётчику.
3. Окно: «У <ФИО> было N открытые/открытых задач» (склонение), список задач с галочками (все отмечены), «Передать: [действующие сотрудники ▾]», «Назначить» / «Позже» («Закрыть», когда обрабатывать нечего). При открытии каждая задача перечитывается (`GET ?id=`) — берётся свежая `version` и состав исполнителей.
4. «Назначить» — последовательные PUT `{version, assignees}` по отмеченным задачам. У смешанной задачи (есть другой действующий исполнитель) PUT = `оставшиеся + получатель` (второго исполнителя не затираем; в окне подпись «Остаётся исполнителем: …»).
   - 422 `TASK_BLOCKED_BY_SICK_OR_TRIP`: задача не переназначается, в окне причина (дата — ФИО — больничный/командировка) и «Принять предложенную дату» (PUT с `start_at/end_at` из `suggested_*`, как в форме); остальные задачи переназначаются. Смена получателя сбрасывает старые блокировки.
   - 409 `VERSION_CONFLICT`: задача перечитывается и PUT повторяется один раз; если за это время её закрыли/архивировали или назначили исполнителя — «пропущена» с пояснением, без повторного PUT; второй 409 → ошибка у задачи.
   - 400 `employee_not_found` (получатель удалён, пока окно открыто): ошибка в окне, получатель сбрасывается, справочник обновляется.
   - после успешных назначений: `tasks:changed` (матрица), обновление счётчика ⚠ и открытой панели.
5. «Позже» / Esc — закрыть окно, задачи остаются в счётчике ⚠.
6. supervisor/viewer: все пометки видны, «Назначить» не рендерится, `offerReassign` ничего не делает (проверено тестом, запросов записи нет).

Дополнительно (нужно для корректной работы с удалёнными исполнителями):
- форма правки: удалённые исполнители не попадают в чипы/`assignees` (иначе PUT получил бы 400 `employee_not_found`); если состав действующих не менялся — PUT уходит **без** `assignees`, snapshot удалённого сохраняется; для задачи «без исполнителя» разрешено сохранять правку текста/срока без выбора исполнителя;
- `hasAssignee` (фильтр/подсветка) больше не считает удалённых;
- справочник сотрудников перечитывается при каждом открытии вкладки (после удаления он иначе устаревал).
