# ТЗ: блок «Задачи» (T1, MVP) — v0.2 НА УТВЕРЖДЕНИИ
Основание: `BFT.md` v1.0 (утверждён). Макеты: `mockups.html`. Не запускать без «Старт»; деплой — только по «Деплой».

## 1. Модель данных (SQLite, миграция v7)
- `tasks(id TEXT PK, title TEXT NOT NULL, description TEXT, start_at TEXT NOT NULL, end_at TEXT, priority INTEGER 1..3, label TEXT, status TEXT CHECK(status IN('open','closed')) DEFAULT 'open', check_state TEXT ('ok'|'pending') DEFAULT 'pending', version INTEGER DEFAULT 1, created_by, created_at, updated_at, closed_at, archived INTEGER DEFAULT 0)`. Время хранится как локальное +05 (ISO без смещения); срок без периода — `end_at = NULL`.
- `task_assignees(task_id, employee_id, role TEXT ('assignee'|'watcher'), PRIMARY KEY(task_id, employee_id, role))`; FK ON DELETE CASCADE.
- `task_checklist(id, task_id, text, done INTEGER, sort_order)`.
- Индексы: `(start_at)`, `(status)`, `task_assignees(employee_id)`.

## 2. API (`api/tasks.php`, отдельно от save.php)
| Метод | Назначение | Роль |
|---|---|---|
| GET `?from=&to=&employee_id=` | задачи диапазона + вычисленные поля `first_day`, `conflict` | admin/supervisor/viewer |
| GET `?id=` | карточка | все |
| POST | создать (после проверки FR-10) | admin |
| PUT `?id=` (с `version`) | править/переназначить | admin |
| POST `?id=&action=close\|reopen` | сменить статус | admin |
| DELETE `?id=` | архив | admin |
| GET `?calendar_facts&employee_id=&from=&to=` | факты матрицы для n8n (токен) | сервис |
Ошибки: 409 `VERSION_CONFLICT`, 422 `TASK_BLOCKED_BY_SICK_OR_TRIP` (с `suggested_start`), 403. Каждая мутация — запись в audit_log. Ответ списка включает только необходимые поля (без телефонов).

## 3. Правила (детерминированные, FR-10/11)
1. Дни задачи = все даты от `start_at` до `end_at` (или одна).
2. Для каждого исполнителя: день с `schedule_entries.status ∈ {sick, trip}` или записью `trips` → блок. Выходной/праздник/отпуск → допустимо, только пометка.
3. `suggested_start` = ближайшая дата ≥ start, начиная с которой весь период помещается вне блокирующих дней.
4. `conflict` для существующей открытой задачи вычисляется при GET.
Реализация правил — workflow n8n (вариант B): webhook `tasks-validate` получает {employees, from, to}, запрашивает `calendar_facts`, возвращает {blocked_days, suggested_start, notes}. Таймаут 3 с; при отказе — `check_state='pending'`, перепроверка workflow по расписанию.

## 4. Интерфейс
1. Панель «Задачи», по умолчанию вид «Список» (2.2); переключатель Список | Доска | Календарь. Клик по фамилии → Доска (2.1), отфильтрованная по сотруднику; клик по задаче → Доска с выделенной карточкой. Вид «Календарь» (2.3) — неделя/день, показывает ВСЕ задачи всех сотрудников, в плитке ФИО и описание (при ≤1 строке описание обрезается с «…»). Для supervisor/viewer все действия записи скрыты и закрыты на API.
2. Иконка в ячейке матрицы — ВАРИАНТ B (круг `#0088CC` со счётчиком открытых задач, стартующих в этот день; красный круг, если у любой из них признак `conflict`) на первом дне открытой задачи + тонкая рамка срока (`1.5px solid var(--rt-blue)`, radius 8, как у `.photo`).
3. Клик по иконке → панель в виде «Календарь» (2.3), неделя с этим днём, плитки сотрудника подсвечены; фильтр «все/сотрудник» переключаемый. [Допущение: исходное требование Q5 — переход как в Outlook; основной вид по умолчанию остаётся «Список».]
4. Mobile compact (P13): рамка и иконка не ломают скролл матрицы.
Ограничение: матрица рисуется в `index.html`; правка точечная, без изменения обработчиков sync/save.

## 5. LLM-функции (этап после ядра и n8n)
Через n8n, 4 workflow (`llm-draft`, `llm-load`, `llm-digest`, `llm-label`). На вход — фамилии и тексты; без телефонов/фото/токенов. Ответ — JSON, валидируется схемой; в БД пишет только подтверждённое admin действие через `api/tasks.php`. Дайджест — только отправка admin (канал определим в T2; в T1 — показ в панели).

## 6. Критерии приёмки
- AC-1 admin создаёт/правит/закрывает/переоткрывает задачу; supervisor и viewer получают 403 на любую запись и видят иконки и панель.
- AC-2 иконка только на первом дне открытой задачи; рамка по всему сроку; закрытая задача иконки не имеет.
- AC-3 срок через выходной/праздник/отпуск сохраняется; через больничный/командировку — 422 с `suggested_start`.
- AC-4 запись больничного поверх задачи не блокируется, задача получает `conflict`.
- AC-5 устаревшая вкладка: PUT со старым `version` → 409, данные не затираются.
- AC-6 smoke API ≥ существующих (44/44) + новые тесты задач; e2e: создать → иконка → панель → закрыть.
- AC-7 audit_log содержит все мутации.
- AC-8 n8n недоступен → задача сохраняется как `pending`, UI показывает пометку.
- AC-9 LLM не получает запрещённых полей (тест на payload).
