# IE-1 — сьют `refs` в verify_all.sh: удалённые/переименованные функции без оставшихся ссылок

Role: implementer (gate tooling). Delivery owner: software-development-coordinator. Return: Kanban-квитанция + отчёт в репозитории.
Решение владельца 2026-11-16: механически закрыть запрет политики «нельзя удалять/переименовывать по индексу» (AGENTS.md → «Индекс кода: навигация, не истина», правило 2).

## Objective

`bash scripts/verify_all.sh` должен падать (`GATE: FAIL`), если в проверяемом диффе удалена или переименована именованная функция, а где-либо в репозитории остались ссылки на старое имя. Сейчас такой дефект gate не ловит.

## Контекст (проверено координатором на коммите 56fecf8)

- `js/trips.js:1472` — `function maskPhoneField(el)`; единственная ссылка — HTML-строка `oninput="window.Trips.maskPhoneField(this)"` в `js/trips.js:1162`. Статические инструменты такую ссылку не видят.
- `api/db.php:102` — `public function migrate()`; вызовы вида `$db->migrate()` в 19 продакшен-файлах `api/`, например `api/load.php:32`, `api/save.php:67`.
- `js/trips.js:987` — `function createTripModal()`; других вхождений имени в коде нет (`rg -w` по репозиторию без `reports/` и `*.md` даёт только строку определения).
- Устройство gate: `scripts/verify_all.sh` — массив `BASELINE`, список `ALL_SUITES`, функция `run_suite` (ветка `case` на сьют, заполняет `RES`/`CNT`/`NOTE`), сравнение `git status` до и после прогона.

Номера строк — для ориентации; перед использованием перечитай файлы.

## Требуемое поведение проверки

1. **База сравнения.** Переменная окружения `VERIFY_BASE`; по умолчанию `git merge-base HEAD origin/main`. Сравнивается база с текущим рабочим деревом (включая незакоммиченные правки). Нет `origin/main` или база равна текущему состоянию — PASS с пометкой «удалённых функций: 0».
2. **Что считается удалённой функцией.** Имя, у которого в базе было определение в продакшен-файлах (`index.html`, `js/*.js` кроме `js/test_*`, `api/*.php` кроме `*_test.php`, корневые `*.php`), а в текущем дереве в этих файлах определения с таким именем нет нигде. Формы определения: `function name(` (JS и PHP, включая методы классов), `name: function(`, `name = function(`, `const|let|var name = (...) =>` и `= async ...`. Переименование = удаление старого имени.
3. **Поиск ссылок.** Для каждого удалённого имени — поиск целого слова по всем отслеживаемым git текстовым файлам текущего дерева, кроме `reports/`, `staff_project/`, `*.md`, `CODEMAP.md`. Ссылкой считается любое вхождение вне строки-комментария: вызов, `->name(`, `window.X.name`, строковый литерал, HTML-атрибут `on*=`, тесты в `scripts/`. Сама проверка не использует CodeGraph и CODEMAP.
4. **Результат.** Есть ссылки — FAIL, по каждому имени список `файл:строка: текст`. В таблицу gate: `CNT` = число пройденных самотестов, `NOTE` = «удалено N, со ссылками M, исключений K».
5. **Исключения.** `scripts/removed_refs_allow.txt`, формат строки: `имя  # причина`. Имя из списка не роняет gate, но число исключений всегда видно в `NOTE`. Пустая причина — ошибка формата (FAIL).
6. **Сьют `refs`** запускает самотесты и затем реальную проверку текущего диффа. Добавить в `ALL_SUITES` и `BASELINE`.

## Acceptance Criteria

Самотесты работают на временной копии дерева в `$TMPDIR` (например `git worktree add --detach` или `git archive`), рабочее дерево и `data/app.db` не трогают, за собой убирают (включая `git worktree prune`). Обязательные случаи:

1. Удалить определение `maskPhoneField` → FAIL, в выводе есть `js/trips.js:1162`.
2. Удалить `Database::migrate` → FAIL, перечислены не менее 19 мест в `api/`, среди них `api/load.php` и `api/save.php`.
3. Удалить `createTripModal` → PASS.
4. Переименовать функцию и обновить все ссылки → PASS.
5. Переименовать функцию, оставив одну ссылку в `index.html` → FAIL с `index.html:<строка>`.
6. Удалить метод объектного литерала (`name: function`), на который есть ссылка → FAIL.
7. Удалённое имя встречается только в комментарии → PASS.
8. Имя внесено в `removed_refs_allow.txt` с причиной → PASS, в `NOTE` исключений: 1; та же строка без причины → FAIL.
9. Дифф без удалений → PASS, «удалённых функций: 0».
10. `VERIFY_BASE` указывает на несуществующий коммит → FAIL с понятным сообщением, а не PASS.

Плюс:
11. `bash scripts/verify_all.sh` на твоём итоговом коммите → `GATE: PASS`, сьют `refs` в таблице, строка `clean PASS`.
12. `bash scripts/verify_all.sh refs` выполняется не дольше 60 с.
13. `git status --porcelain` после прогона пуст; в `git diff --stat` относительно стартового коммита нет продакшен-файлов.
14. Сообщения проверки на русском; в сообщении FAIL сказано, что делать (обновить ссылки или внести исключение с причиной).
