### Правило (как реализовано)
- **Код** — любой путь вне `reports/**`, `staff_project/**`, `*.md` (`ct_is_doc`, `scripts/lib_commit_tasks.sh:13`). Пути берутся `git diff-index --cached --name-only --no-renames -z` (индекс на момент хука — для `commit -a`/`commit <path>` git подставляет нужный индекс).
- **id** — `t_[0-9a-f]{8}` как отдельное «слово» (не `at_a1b2c3d4`, не 9 hex, не `T_`); из сообщения вырезаются строки-комментарии (`#…`) и всё после «ножниц» `# ---- >8 ----` (дифф `commit -v`).
- **Существование** — `sqlite3 -readonly` по `$KANBAN_DB` (по умолчанию `$HOME/.hermes/kanban.db`), `SELECT id FROM tasks WHERE id IN (…)`; хотя бы один найден — OK.
- БД/`sqlite3` недоступны или не читаются → проверяется формат, в stderr предупреждение, коммит не блокируется.
- Merge (`MERGE_HEAD`) → пропуск. Коммит только с документами / пустой → пропуск.
- Сьют `tasklink`: FAIL, если `core.hooksPath` ≠ `scripts/hooks`; хука нет / не исполняемый в дереве / в индексе не `100755`; самотесты не прошли; `check_commit_tasks.sh` нашёл нарушения в `origin/main..HEAD`. `CNT` = число пройденных самотестов. Проверка диапазона в gate запускается с `env -u KANBAN_DB -u KANBAN_SQLITE3` — подменой БД через окружение gate не обойти.

## 4. Пункт 14: `--amend`, `revert`, `cherry-pick`, `rebase` (проверено запуском)

Скрипт `reports/IDX_ENFORCE/IE-2_flows_probe.sh` (временные репозитории, хук обёрнут журналом вызовов; git 2.43). Каждый сценарий — свежий репозиторий; «хук вызван раз» считает обёртка.

| Операция | Хук вызывается? | Что происходит | Что требуется от автора |
|---|---|---|---|
| `git commit --amend -m "…без id"` (HEAD с кодом и id) | **да** | отказ, exit 1, HEAD не изменён | в новом сообщении сохранить id. Хук для `--amend` сравнивает с родителем HEAD (по `--amend` в командной строке родительского процесса; Linux `/proc`), иначе правка «только документ» стёрла бы id кода |
| `git commit --amend --no-edit` | **да** | сообщение (и id) сохранено → проходит | ничего |
| `git revert` (`--no-edit` и `-e`) | **нет** | коммит создан всегда; сообщение `Revert "<тема исходного>"` несёт id исходной темы, если он там был; `revert -e` с сообщением без id тоже создан | убедиться, что id есть; иначе `git commit --amend -m "… (t_xxxxxxxx)"` (амэнд проходит хук). Не поймано хуком — ловит gate |
| `git cherry-pick` (в т.ч. `-e`) | **нет** | сообщение копируется (id сохраняется); `-e` с сообщением без id создан | то же: id в сообщении; иначе amend. Если исходный коммит без id — gate ловит |
| `git rebase <base>` (обычный) | **нет** (для переносимых коммитов) | коммиты переносятся с прежними сообщениями; коммит без id остаётся без id | rebase не «лечит» и не создаёт нарушений; ловит gate по диапазону |
| `rebase -i`, `reword` | **да** | сообщение без id → отказ, rebase останавливается (exit 1); `git rebase --abort`/исправить и `--continue` | указать id в новом сообщении |
| `rebase -i`, `edit` + `git commit --amend` | **да** | как обычный amend | id в сообщении |
| `rebase -i`, `squash` (редактируемое объединённое сообщение) | **нет** | объединённый коммит создаётся даже без id | следить, чтобы id был в итоговом сообщении; ловит gate |
| `git merge --squash` + `git commit` | **да** (обычный коммит) | без id → отказ | id в сообщении |
| `git merge` (с `MERGE_HEAD`) | да, но пропуск по правилу 4 | создан без id | — |

## 5. Известные способы обхода и чем обнаруживаются

| Обход | Обнаруживается? |
|---|---|
| `git commit --no-verify` | **gate**: `check_commit_tasks.sh` по `origin/main..HEAD` (проверено, §3 п. 3, случай 9) |
| `git -c core.hooksPath=… commit`, `git config --unset core.hooksPath`, клон без включённого хука | gate: проверка `core.hooksPath` + проверка диапазона (§3 п. 1) |
| Правка/удаление/обезвреживание хука, снятие `+x` | gate: `+x` в индексе и в дереве, самотесты (тестируют хук из репозитория); изменение видно в диффе |
| Подмена `KANBAN_DB` / `KANBAN_SQLITE3` фикстурой с фальшивым id в момент коммита | хук примет (так задано спецификацией); gate игнорирует эти переменные (`env -u`) и сверяет с реальным Kanban → нарушение (§3 п. 6 — тот же механизм) |
| `revert` / `cherry-pick` / `rebase` (pick, squash) без id в сообщении | хук не вызывается (см. §4); gate по диапазону |
| Чужой/посторонний существующий id в сообщении | **не обнаруживается** механически (проверяется только существование); ловит ревью |
| Код в `reports/**` или в файле `*.md` (документ по спецификации) | **не обнаруживается** (так задан список документов); возможное ужесточение — ограничить `reports/**` расширениями документов |
| Код, внесённый в merge-коммит (разрешение конфликтов «злого» merge) | **не обнаруживается** (merge пропускается по п. 4 спецификации, `check_commit_tasks.sh` merge тоже пропускает) |
| Нарушающий коммит уже попал в `origin/main` (после push) | gate его больше не видит (диапазон `origin/main..HEAD`); поэтому gate обязателен до push; чтобы проверить историю целиком — `bash scripts/check_commit_tasks.sh <диапазон>` (старые коммиты до IE-2, в т.ч. V7, нарушения дадут) |
| БД Kanban/`sqlite3` недоступны | хук и gate проверяют только формат id (по спецификации); в NOTE gate строка «БД Kanban недоступна — только формат id», в stderr хука — предупреждение |
| Linked worktree на ветке/коммите, где ещё нет `scripts/hooks` (относительный `core.hooksPath` указывает в пустоту) | хук молча не запускается; ловит gate в основном checkout по диапазону |
| Не-Linux/обёртки: определение `--amend` по `/proc/$PPID/cmdline` | при сбое определения хук сравнивает с `HEAD` (мягче: правка «только документ» при `--amend` не ловится); ловит gate по диапазону |
