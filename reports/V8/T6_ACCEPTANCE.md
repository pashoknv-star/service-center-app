## 4. Найденные дефекты

### P1-1 — телефон: набор по цифрам «8…»/«7…»/«+7…» даёт неверный номер (п.1 владельца)

Шаги: admin → «Командировки» → «+ Новая командировка» → клик в поле «Телефон сотрудника» (появляется «+7 ») → набрать на клавиатуре `89991234567` (цифра за цифрой).
Ожидаемо (слова владельца: «`89991234567` нормализуется»): «+7 (999) 123-45-67».
Фактически: «+7 (899) 912-34-56» — первая «8» остаётся цифрой номера, одиннадцатая цифра отбрасывается. Ошибки валидации нет (получилось ровно 10 цифр), форма сохраняется; в БД телефон уже неверный (`+789****3456`). Так же: `79991234567` → «+7 (799) 912-34-56», `+79991234567` → «+7 (799) 912-34-56». Верно: вставка (`Input.insertText` целиком) — «+7 (999) 123-45-67»; набор `9991234567` — «+7 (999) 123-45-67».
Причина (прочитано в `js/trips.js`, `phoneNationalDigits` / `maskPhoneField`): префикс 7/8 отбрасывается только когда в поле **ровно 11 цифр** за один раз (вставка); при посимвольном вводе после первой «8» нет 11 цифр, и «8» считается национальной цифрой. Сьют `tripsform` не ловит: в `scripts/test_trips_v8_form.js:202–209` целые номера (8…/7…/+7…) проверяются только вставкой, по символам набирается лишь «999».
Серьёзность P1: тихая порча номера, который уходит в payload робота (`employee.phone`); пользователь — набирающий «8 999 …», как привык, — не получает ни ошибки, ни подсказки. Воспроизводится на 1440 и 375 px.
Скриншоты: `T6_a1440_phone_typed.png`, `T6_a375_phone_typed.png` (на 375 тот же результат «+7 (899) 912-34-56»).

### P2-1 — Матрица: после выделения диапазона протяжкой меню не остаётся (не регрессия V8)

Шаги: admin → «Матрица отпусков» → зажать кнопку на ячейке дня, протянуть по строке сотрудника на 4 дня (07–10.12), отпустить.
Ожидаемо: открывается меню «Рабочий день / Отпуск / Больничный / Командировка / Отгул / Очистить» с заголовком диапазона.
Фактически: ячейки подсвечены (`range-selecting`), меню нет; следующий одиночный клик по дню «проглатывается» (`rangeActive`). Диагностика: `mouseup` на документе открывает меню, затем браузер отправляет `click` на общего предка (`TR.matrix-hover-row`, так как нажатие и отпускание — на разных ячейках), «единый обработчик клика вне меню» (`index.html:~3680`) закрывает меню.
**Воспроизводится идентично на `80577c5` (до V8)** — запущен тот же сценарий на `git archive 80577c5`: журнал событий тот же. То есть не регрессия V8; но пункт владельца «создание командировки из Матрицы (выделение диапазона)» этим путём не работает (в Chromium 145). Обходные пути работают: клик по дню → «Командировка» (R1), Ctrl+клик по строкам → клик по дню (R2). В других браузерах и на проде не проверялось (вызовы прода запрещены). Рекомендация: решить владельцу/координатору (отдельная задача).
