3. Рабочие допущения

A1. Стек
Frontend:
- vanilla HTML/CSS/JS;
- ES modules;
- без фреймворка;
- без сборщика.

Backend:
- PHP 8+;
- без фреймворка;
- SQLite или JSON как хранилище;
- GD/Imagick для обработки фото.

A2. Данные

Текущее состояние:
- данные хранятся в localStorage;
- серверного API пока нет.

Целевое состояние:
- сохраняем совместимость с localStorage как временным хранилищем;
- проектируем серверный API.

A3. Статусы
Финальный набор статусов:
Код | Название | Назначение | Комментарии
vacation | Отпуск | Основной отпуск | не обязателен
sick | Больничный | Болезнь | не обязателен
trip | Командировка | Рабочая поездка | Город, задача
day_off | Отгул | Дополнительный выходной | причина
work | Рабочий день | Явное указание рабочего дня | не обязателен 
empty | Очистить | Сброс статуса | отсуствтует

A4. Редактирование
Базовый сценарий:
1. Пользователь кликает по ячейке дня.
2. Или выделяет диапазон дней.
3. Открывается меню выбора статуса.
4. Пользователь выбирает статус.
5. Для trip/day_off вводится комментарий.
6. Статус применяется к выбранной ячейке или диапазону.
7. Инструмент «Очистить» удаляет статус.

A5. Сохранение
До появления серверного API сохраняется текущая конфигурация:
Использовать localStorage как временное хранилище.
Кнопка «Сохранить расстановку» сохраняет состояние.
Кнопка «Сбросить» возвращает к последнему сохранённому состоянию после подтверждения.

Позже слой хранения должен быть заменяемым на серверный API.

A10. Запрет на разрушающие изменения
При доработках нельзя:
Ломать текущую структуру данных без миграции.
Удалять существующих сотрудников.
Менять поведение кнопок без согласования.
Терять уже введённые данные.
Ухудшать доступность и производительность.
Т.е.
Продуктовое удаление сотрудников разрешено.
Программная потеря данных при доработке запрещена.
